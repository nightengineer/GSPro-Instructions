# GSPro: настройка и восстановление на новом VPS

Версия мастера: **1.0.0**. Редакция инструкции: **1.0.1**, 28.09.2026. Публичные инструкции: [GSPro-Instructions](https://github.com/nightengineer/GSPro-Instructions). Инструкция предназначена для восстановления сохранённого рабочего комплекта GSPro из S3 на новом VPS с доменом **gspro.store**. ОС нового сервера: **Ubuntu 24.04, x86_64**. Команды ниже выполняет владелец сервера в SSH-терминале от root.

## Самый простой способ: интерактивный мастер

Выберите этот порядок для обычного восстановления: мастер сам возьмёт ключи из снимка, спросит недостающие значения и подготовит нужные файлы. Вручную редактировать `.env` и S3 JSON для этого пути не требуется. Подробности каждого шага идут после короткой последовательности.

1. Откройте терминал нового Ubuntu 24.04 от root. Если вошли обычным пользователем, выполните `sudo -i`. Публичный пакет будет скачан прямо на сервер.
2. Установите минимальные зависимости и распакуйте мастер:

```bash
umask 077
apt-get update
apt-get install -y python3 python3-boto3 python3-cryptography \
  openssl ca-certificates curl unzip openssh-client
install -d -m 700 /root/gspro-recovery /root/gspro-server-setup
GSPRO_DOCS_URL=https://raw.githubusercontent.com/nightengineer/GSPro-Instructions/main
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip" -o /root/GSPro-Server-Setup.zip
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip.sha256" -o /root/GSPro-Server-Setup.zip.sha256
cd /root
sha256sum -c GSPro-Server-Setup.zip.sha256
unzip -n /root/GSPro-Server-Setup.zip -d /root/gspro-server-setup
cd /root/gspro-server-setup
sha256sum -c SHA256SUMS
```

3. Запустите `python3 fetch-recovery-kit.py`: выберите S3 и введите доступы скрыто. Затем по разделу 4 скачайте полный снимок на VPS, расшифруйте его и проверьте SHA256. Подготовьте публичный ключ `/root/owner-public-key.pub` по разделу 0.4. В результате снимок должен лежать в `/root/restore-prod11`, комплект - в `/root/gspro-recovery/recovery-kit`.
4. Запустите опрос и ответьте на вопросы. Это самая короткая команда: все пути уже заданы по умолчанию.

```bash
cd /root/gspro-server-setup
python3 configure-gspro.py
```

5. Проверьте сводку и по очереди выполните установку и применение. После успешного завершения installer запускайте следующую команду:

```bash
less /root/gspro-setup/setup-summary.md
bash /root/gspro-setup/deploy-new-vps.configured.sh
python3 /root/gspro-server-setup/configure-gspro.py --apply /root/gspro-setup
```

6. Проверьте образы, оба S3 и DNS, затем запустите сайт и единственного бота по разделам 12-13. После успешной новой резервной копии включите расписание по разделу 14.

Это восстановление данных существующего GSPro. Без полного снимка мастер не сможет сохранить исходные ключи и восстановить рабочий проект. Автоматически публиковать сайт после опроса он не будет.

## 0. Начать на чистом Ubuntu-сервере

Этот порядок подходит для нового пустого Ubuntu 24.04 без Docker и без GSPro. Сначала подготавливается терминал и скачивается снимок из S3. Мастер настройки запускается после этого: он читает исходные ключи и конфигурации снимка, поэтому не может подготовить рабочий комплект без снимка.

### 0.1. Войти от root и проверить сервер

Откройте консоль нового VPS у провайдера либо его начальную SSH-сессию. Если вошли обычным пользователем с правами sudo, перейдите в root:

```bash
sudo -i
```

Если вы уже root, эта команда не нужна. Проверьте систему:

```bash
id -u
cat /etc/os-release
uname -m
df -h /
```

Ожидается UID `0`, `ID=ubuntu`, `VERSION_ID="24.04"`, архитектура `x86_64`. Проверьте свободный диск и доступ сервера к репозиториям Ubuntu и выбранному S3. Действующий сервер GSPro для этих команд не используется.

### 0.2. Установить минимум для подготовки

На новом сервере выполните:

```bash
umask 077
apt-get update
apt-get install -y python3 python3-boto3 python3-cryptography \
  openssl ca-certificates curl unzip openssh-client
install -d -m 700 /root/gspro-recovery /root/gspro-server-setup
python3 --version
```

На Ubuntu 24.04 системный Python подходит мастеру. Отдельный virtualenv, pip и предварительная установка Docker не нужны. Boto3, cryptography и OpenSSL нужны инструментам скачивания/расшифровки, а сам `configure-gspro.py` использует стандартную библиотеку Python. Docker позже установит штатный installer.

### 0.3. Разместить пакет мастера и проверить запуск

Для загрузки пакета используйте [открытый репозиторий инструкций GSPro](https://github.com/nightengineer/GSPro-Instructions). Команды ниже выполняются после публикации пакета:

```bash
GSPRO_DOCS_URL=https://raw.githubusercontent.com/nightengineer/GSPro-Instructions/main
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip" -o /root/GSPro-Server-Setup.zip
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip.sha256" -o /root/GSPro-Server-Setup.zip.sha256
cd /root
sha256sum -c GSPro-Server-Setup.zip.sha256
```

Этот небольшой пакет содержит инструменты, документы и контрольные суммы. Полный снимок и защищённый recovery-kit владелец получает отдельно из своего S3. Контрольная сумма пакета из GitHub должна завершиться `OK`.

Распакуйте его в подготовленный пустой каталог:

```bash
unzip -n /root/GSPro-Server-Setup.zip -d /root/gspro-server-setup
cd /root/gspro-server-setup
sha256sum -c SHA256SUMS
chmod 700 configure-gspro.py
python3 configure-gspro.py --version
python3 configure-gspro.py --help
```

Должны появиться пять `OK`, версия `1.0.0` и справка. Эти команды ещё не запускают опрос или восстановление. Если распаковка показывает пропуск уже существующих файлов, используйте новый пустой каталог и проверенные файлы пакета.

### 0.4. Подготовить публичный SSH-ключ владельца

Нужна одна строка публичного OpenSSH-ключа, например начинающаяся с `ssh-ed25519`. Приватный ключ на сервер для этого шага не вводится. Чтобы записать публичную строку в терминале:

```bash
cat > /root/owner-public-key.pub
```

Вставьте одну строку вашего публичного ключа, нажмите Enter, затем Ctrl+D. После этого:

```bash
chmod 600 /root/owner-public-key.pub
ssh-keygen -lf /root/owner-public-key.pub
```

Сверьте отпечаток с ключом, которым владелец будет входить. Штатный installer впоследствии добавит его в `authorized_keys` и отключит вход по паролю. До проверки входа по ключу сохраняйте текущую консоль сервера.

### 0.5. Порядок дальнейшего запуска

1. По разделу 4 скачайте recovery-kit и полный снимок из S3 непосредственно на VPS, расшифруйте и проверьте SHA256.
2. По разделу 5 выполните `python3 configure-gspro.py` в SSH-терминале и ответьте на вопросы. Получится `/root/gspro-setup`.
3. По разделу 7 отдельно запустите созданный `deploy-new-vps.configured.sh`: он установит Docker и восстановит данные.
4. По разделу 7.2 выполните `configure-gspro.py --apply`: он применит подготовленные env и S3-настройки.
5. По разделам 12-14 проверьте образы/S3/DNS, запустите сайт и единственного бота, затем подтвердите новую копию и включите расписание.

Не меняйте порядок: опрос нужен до installer, а `--apply` - после staged restore, когда приложение и БД уже восстановлены, но публичные службы ещё остановлены.

## 1. Что входит в пакет и что делает мастер

- `fetch-recovery-kit.py` - начальная загрузка закрытого recovery-kit из S3 со скрытым вводом ключей. Требует boto3; доступы остаются только в памяти процесса.
- `configure-gspro.py` - интерактивный мастер. Требует Python 3.10 или новее; сам использует только стандартную библиотеку.
- `Инструкция_настройки_GSPro.md` и одноимённый PDF - одна инструкция в двух форматах.
- `Проверка_мастера.json` - результат испытаний и их ограничения.
- `SHA256SUMS` - контрольные суммы файлов этого пакета.

Мастер сначала **готовит** настройки в новой приватной папке. Он проверяет исходный комплект и снимок, спрашивает IP нового VPS, SSH-параметры и доступы к двум S3. Ключи шифрования, пароли БД и теги образов берёт из снимка. При необходимости предлагает изменить контакты, ограничения и токены интеграций. Ввод секретов скрыт; Enter оставляет сохранённое значение.

Подготовка не устанавливает программы и не обращается в сеть. Созданный `deploy-new-vps.configured.sh` - отдельная настроенная копия штатного установщика. В ней принудительно сохранено `START_PUBLIC_SERVICES=false`, а `RELEASE_VARIANT` пустой. Оригинальные файлы recovery-kit и snapshot не переписываются.

После восстановления команда `--apply` записывает только девять файлов проекта: три env, четыре файла S3 и два исходных файла recovery-kit. Она сохраняет предыдущие версии, проверяет неизменяемые ключи по исходному снимку, берёт блокировки deployment/backup и отказывает, если публичные контейнеры уже работают. Сайт, бот и таймеры эта команда не запускает.

**Штатный установщик при отдельном запуске изменяет новый VPS:** устанавливает Docker и пакеты, настраивает SSH, UFW, fail2ban, обновления, swap и выбранные systemd units. Запускайте его только на предназначенном для восстановления новом пустом сервере. При подготовке этой инструкции установка на VPS не выполнялась.

## 2. Что нужно подготовить владельцу

Запишите несекретные параметры. Доступы держите отдельно и вводите непосредственно в терминале мастера.

| Параметр | Где взять / что решить | Куда попадёт |
| --- | --- | --- |
| Публичный IP нового VPS | Панель провайдера; фактический адрес сервера | `NEW_SERVER_IP` в настроенном установщике; DNS меняется отдельно |
| SSH port | Обычно 22; при смене проверьте firewall провайдера и доступ по новому порту | `SSH_PORT`; установщик настроит sshd и UFW |
| Публичный SSH-ключ | Ваш файл `.pub`; приватный ключ остаётся у владельца | `owner-public-key.pub`, затем `/root/.ssh/authorized_keys` |
| IP внешнего мониторинга | Фактические адреса системы мониторинга; `-` отключит правило 10050 | Массив `MONITORING_IPS`; агент мониторинга отдельно |
| Timeweb Access/Secret Key | Панель владельца S3; ключи для нужного бакета | `/root/backups/s3-credentials.json` |
| REG.RU Access/Secret Key | Панель владельца S3; ключи для нужного бакета | `/root/backups/regru-s3-credentials.json` |
| Пароль ключа восстановления | Ранее установленный пароль encrypted PEM | Только скрытый ввод при расшифровке; мастер настройки его не спрашивает |
| Доступ к DNS gspro.store | Панель DNS домена | Записи A/AAAA; в env IP не подставляется |
| Доступ в админку и 2FA | Восстановленные учётные записи владельца | Проверка прав, SMTP и приёма платежей в интерфейсе |

Для восстановления нужны сохранённые образы и полный снимок, а не только исходники сайта. Ориентир ресурсов нового VPS: от 2 vCPU, 2 ГБ RAM и 40 ГБ диска; оставьте место для снимка, образов и локальных копий при сбое S3. Это минимальный ориентир, не расчёт нагрузки.

Для регулярного резервного копирования S3-ключам нужны List/Get/Put/Delete в используемом префиксе. Ключ только на чтение подходит для скачивания, но не для будущих копий и ротации.

Не отправляйте секреты в чат и не вставляйте их в команды shell. Не включайте `set -x`, запись SSH-сессии или вывод полных `.env`, `containers.json`, `docker inspect` контейнеров. Эти файлы и команды могут содержать секреты.

## 3. Каталоги и файлы на сервере

| Путь | Назначение | Кто создаёт / меняет |
| --- | --- | --- |
| `/root/gspro-recovery/recovery-kit/` | Оригинальный независимый комплект восстановления | Скачивание из S3 на VPS; мастер только читает |
| `/root/restore-prod11/` | Распакованный полный снимок с `SHA256SUMS` | Скачивание из S3, расшифровка и распаковка на VPS; мастер только читает |
| `/root/gspro-server-setup/` | Скрипт мастера и данная инструкция | Владелец размещает и проверяет пакет на VPS |
| `/root/gspro-setup/` | Результат опроса: приватные настройки и настроенный installer | Мастер создаёт новый каталог, права 700 |
| `/root/gspro-setup/app/` | Подготовленные `.env`, `.env.runtime`, `.env.telegram` | Мастер; файлы 600 |
| `/root/gspro-setup/backups/` | Подготовленные configs/credentials S3 и два файла recovery-kit | Мастер; файлы 600 |
| `/root/gspro-setup/setup.json` | Карта SHA256, исходных ключей и ID образов без их секретных значений | Мастер; не редактировать вручную |
| `/root/gspro-setup/setup-summary.md` | Краткая несекретная сводка и следующие команды | Мастер |
| `/root/gspro-setup/previous-config/` | Предыдущие версии файлов перед `--apply` | Мастер при применении; содержит секреты, права 700/600 |
| `/root/gspro-setup/applied.json` | Отметка завершённого применения | Мастер; повторное применение этой папки запрещено |
| `/opt/gspro/` | Восстановленное приложение | Штатный installer |
| `/root/backups/` | Система резервного копирования | Installer, затем `--apply` для согласованного набора файлов |

Не выбирайте `--output` внутри snapshot, recovery-kit, `/opt/gspro` или `/root/backups`. Папка результата должна быть новой. Не используйте символические ссылки. Вариант размещения приложения фиксирован: `/opt/gspro`.

### 3.1. Какие девять файлов применяются

1. `/opt/gspro/.env`
2. `/opt/gspro/.env.runtime`
3. `/opt/gspro/.env.telegram`
4. `/root/backups/s3-config.json`
5. `/root/backups/regru-s3-config.json`
6. `/root/backups/s3-credentials.json`
7. `/root/backups/regru-s3-credentials.json`
8. `/root/backups/recovery-kit/download-backup.py`
9. `/root/backups/recovery-kit/README.md`

Обновлённый downloader читает endpoint/bucket/region из JSON текущего комплекта. При новой публикации эти настройки попадут в recovery-kit в обоих S3. Это важно, если вы выбрали новые бакеты. Сами S3-credentials в публикуемый recovery-kit не включаются.

## 4. Скачать и проверить исходные материалы из S3

### 4.1. Получить recovery-kit и скачать снимок на VPS

После проверки публичного пакета запустите загрузчик в SSH-терминале:

```bash
cd /root/gspro-server-setup
python3 fetch-recovery-kit.py
```

Он спросит провайдера `regru` или `timeweb`, HTTPS endpoint, имя бакета, регион и два S3-ключа скрыто. Enter принимает показанное значение; для Timeweb имя бакета вводится владельцем. По умолчанию файлы сохраняются в `/root/gspro-recovery`. Папка должна принадлежать текущему пользователю и иметь права 700. Уже существующие архив и checksum не перезаписываются. При повторной попытке используйте новый пустой закрытый каталог.

Загрузчик читает только два объекта: `gspro/recovery-kit/recovery-kit.tar.gz` и `gspro/recovery-kit/recovery-kit.tar.gz.sha256`. Он ограничивает размер архива 128 MiB, сверяет SHA256 до сохранения готового файла и не записывает S3-ключи на диск. При ошибке подробности SDK и значения ключей не выводятся: проверьте endpoint/bucket/region, разрешение чтения этих объектов и сетевой доступ.

В результате оригинальные архив и checksum лежат на VPS. Доступ к S3 должен принадлежать владельцу. Защищённый ключ восстановления будет скачан вместе со снимком командой downloader ниже; его пароль хранится у владельца отдельно.

Для скачивания и расшифровки на Ubuntu нужны Python, boto3, cryptography и OpenSSL. Если они отсутствуют, владелец устанавливает их:

```bash
apt-get update
apt-get install -y python3 python3-boto3 python3-cryptography openssl
umask 077
mkdir -p /root/gspro-recovery
cd /root/gspro-recovery
sha256sum -c recovery-kit.tar.gz.sha256
tar -xzf recovery-kit.tar.gz
cd recovery-kit
sha256sum -c MANIFEST.sha256
python3 download-backup.py regru --kind daily \
  --output /root/gspro-recovery/downloaded
```

Downloader скрыто спросит S3 Access/Secret Key и предложит выбрать полный снимок. Можно выбрать `timeweb` вместо `regru`. При плановом переносе выбирайте согласованный финальный снимок после остановки записи на старом сервере; при полной утрате - последний доступный подходящий снимок.

```bash
cd /root/gspro-recovery/downloaded
sha256sum -c snapshot.cms.sha256
python3 ../recovery-kit/tools/decrypt-cms-stream.py \
  snapshot.cms private.encrypted.pem snapshot.tar.gz
mkdir -m 700 /root/restore-prod11
tar -xzf snapshot.tar.gz -C /root/restore-prod11
cd /root/restore-prod11
sha256sum -c SHA256SUMS
```

При расшифровке пароль PEM вводится скрыто. `private.encrypted.pem` - имя защищённого ключа, скачанного downloader. Убедитесь, что после распаковки `SHA256SUMS` лежит непосредственно в `/root/restore-prod11`, а не во вложенной папке.

Каждая строка проверки должна завершиться `OK`. Если исходный файл отсутствует или хэш не совпал, не продолжайте установку. Проверяйте скачанный архив по checksum из доверенного источника; хэш сам по себе не подтверждает происхождение.

### 4.2. Разместить и проверить пакет мастера на VPS

Размещение и распаковка пакета описаны в разделе 0.3. В `/root/gspro-server-setup` должны находиться `configure-gspro.py`, инструкция, отчёт и `SHA256SUMS`.

```bash
cd /root/gspro-server-setup
sha256sum -c SHA256SUMS
```

Для установки используется корневой `/root/restore-prod11/application.tar.gz` из полного снимка S3 и сохранённые образы `/root/restore-prod11/images.tar.gz`.

## 5. Запустить опрос настроек

### 5.1. Как работает `configure-gspro.py`

У скрипта два режима. Обычный запуск подготавливает новые файлы; `--apply` применяет их к уже восстановленному серверу. Установка системы выполняется отдельным Bash-файлом, а запуск сайта - отдельной Compose-командой.

| Этап скрипта | Что происходит | Что получает человек |
| --- | --- | --- |
| Проверка перед опросом | Root, Ubuntu 24.04, интерактивный терминал, отдельный новый output; сверка SHA256 recovery-kit и snapshot | При ошибке остановка до подготовки настроек |
| Чтение снимка | Три env читаются из `application.tar.gz`; проверяются ключи, runtime-роль, production-режим и теги пяти образов | Исходные секреты данных сохраняются автоматически |
| Опрос | IP, SSH, мониторинг, при необходимости контакты/лимиты/транспортные токены, оба S3 | Ввод в терминале; токены и S3-ключи скрыты |
| Подтверждение сохранения | Показываются путь, IP, домен, SSH port; секреты не выводятся | Ответ `да` создаёт приватный каталог результата |
| Подготовка installer | В копию штатного Bash подставляются ответы и исходные версии; public services выключены | `deploy-new-vps.configured.sh`, готовый к отдельному запуску |
| Подготовка конфигураций | Создаются три env, четыре S3 JSON и обновлённые downloader/README | `app/`, `backups/`, карта hashes `setup.json` и сводка `setup-summary.md` |
| `--apply` после restore | Повторная проверка снимка/ключей, root/прав, hashes и остановленных служб; блокировки, сохранение предыдущих версий | Девять файлов записаны в `/opt/gspro` и `/root/backups`, отметка `applied.json` |

Опрос не проверяет внешние S3/SMTP/Platega/Telegram, не меняет DNS и не запускает installer автоматически. После него следует выполнить проверки и команды следующих разделов.

Скрытый ввод защищает отображение и историю команд; сохранённые env и credentials содержат секретные значения в обычном формате, пригодном для приложения. Поэтому результат хранится под root с правами каталога 700 и файлов 600. Не публикуйте папку `/root/gspro-setup`.

Enter сохраняет предложенное исходное значение. На вопрос подтверждения положительный ответ - `да`, `yes` или `y`; другой ответ означает отказ. Ctrl+C прерывает ввод. Если опрос отменён до сохранения, папки результата нет. Проверяйте наличие `setup-summary.md`, а не только код завершения команды.

### 5.2. Команда основного запуска

Перед опросом положите ваш **публичный** SSH-ключ в `/root/owner-public-key.pub`. Проверить его отпечаток:

```bash
ssh-keygen -lf /root/owner-public-key.pub
cd /root/gspro-server-setup
chmod 700 configure-gspro.py
python3 configure-gspro.py \
  --kit /root/gspro-recovery/recovery-kit \
  --snapshot /root/restore-prod11 \
  --output /root/gspro-setup
```

Порядок вопросов:

1. Публичный IP нового VPS, порт SSH, путь к публичному ключу.
2. IP мониторинга через запятую. По умолчанию оставлены `92.53.116.12`, `92.53.116.111`, `92.53.116.119`; подтвердите, что ваша система действительно использует их. `-` убирает разрешение TCP 10050.
3. Предложение изменить закреплённые версии пакетов. Обычно ответ **нет**: версии берутся из `host-packages.txt` снимка.
4. Предложение изменить контакты, ограничения или токены интеграций. При обычном восстановлении ответ **нет** сохраняет их. Если **да**, мастер спросит 21 редактируемую переменную из разделов 8-9. Enter оставляет исходное; секреты не показываются. Очистка сохранённого значения через пустой ввод не предусмотрена.
5. Для каждого S3 - endpoint, bucket, region, затем скрыто Access Key и Secret Key. Последние отсутствуют в снимке и обязательны для опроса.
6. Показ несекретной сводки и вопрос о сохранении. Только ответ `да`, `yes` или `y` создаёт результат.

Отмена до сохранения не создаёт результат. При незавершённой записи мастер сообщает путь приватного временного каталога. Повторный опрос выполняйте с новым `--output`, например `/root/gspro-setup-2`; не перезаписывайте исходный результат.

## 7. Применить настройку после восстановления

### 7.1. Проверить сводку и выполнить staged restore

```bash
less /root/gspro-setup/setup-summary.md
bash -n /root/gspro-setup/deploy-new-vps.configured.sh
bash /root/gspro-setup/deploy-new-vps.configured.sh
```

Установщик проверяет Ubuntu/root, отсутствие `/opt/gspro`, SHA256 снимка и публичный ключ. Затем ставит окружение, загружает образы, восстанавливает PostgreSQL и SQLite бота, создаёт ограниченную runtime-роль и выбранные units. При наличии скрипта удаления паролей завершённых заказов запускается `purge-completed-passwords.mjs`: это штатная очистка данных после восстановления, поэтому количество таких полей может уменьшиться. Публичные службы и Telegram остаются остановленными.

Установщик не возобновляется автоматически после частичного сбоя. Если он остановился, сохраните сообщение ошибки без секретов, выясните завершённый шаг и продолжайте с конкретного незавершённого действия. Повторный полный запуск на уже заполненном сервере откажет.

После изменения SSH-порта откройте второй терминал и проверьте вход по новому порту, сохранив текущую сессию. Firewall в панели провайдера не меняется установщиком: нужные порты там разрешает владелец.

### 7.2. Применить подготовленные env и S3

```bash
python3 /root/gspro-server-setup/configure-gspro.py \
  --apply /root/gspro-setup
```

Мастер ещё раз проверит исходный снимок, hashes подготовленных файлов, root-владельца и безопасные права каталогов, совпадение исходных ключей в уже восстановленных env, карту образов и production-настройки. При активном deployment/backup он откажет. Подтвердите применение в терминале.

При успешной записи появится `applied.json`, прежние версии сохранятся в `previous-config`. При ошибке мастер пытается вернуть каждую уже записанную версию. Если отдельное восстановление тоже не удалось, он выведет только пути, требующие ручного восстановления из `previous-config`. Не запускайте публичные службы до устранения такого сбоя.

После применения не редактируйте `setup.json` и не повторяйте `--apply` этой папки. Для следующего изменения нужна отдельная настройка и проверка состояния сервера; этот мастер предназначен для первоначального восстановления.

## 8. Полная карта `.env` и `.env.runtime`

Основной файл: **`/opt/gspro/.env`**. Мастер готовит его в `/root/gspro-setup/app/.env`. Все 48 переменных текущего снимка перечислены ниже. Слова «сохранить» означают: значение уже есть в снимке; человек его заново не придумывает.

`/opt/gspro/.env.runtime` - производный файл. Его создаёт `deploy/sync-runtime-env.py` при каждом запуске `deploy/dc`. Он содержит основной env **без** `POSTGRES_PASSWORD`, `POSTGRES_USER`, `POSTGRES_DB`, `DATABASE_URL`. Править runtime отдельно нельзя: изменения будут перезаписаны. Compose формирует runtime `DATABASE_URL` сам из ограниченной роли; отдельный административный URL туда не добавляйте.

### 8.1. Ключи данных и БД: сохранить без замены

| Переменная | Назначение | Как заполнить |
| --- | --- | --- |

## 10. Что заполняется в админке, а не в env

### 10.1. SMTP и отправители

Действующий SMTP хранится в PostgreSQL и восстанавливается с `database.dump`. В этом проекте нельзя решить настройку SMTP добавлением вымышленных `SMTP_HOST`, `SMTP_USER`, `SMTP_PASSWORD` в env: такие поля мастер не создаёт.

После входа владельца откройте раздел настроек почты. Сверьте сервер, порт, пользователя, пароль, включение профилей и адреса отправителей. При изменении пароля вводите обычный новый пароль **в интерфейсе**, который зашифрует его исходным `MAIL_ENCRYPTION_KEY`.

| Хранилище БД | Поля | Где действует человек |
| --- | --- | --- |
| `TechnicalSettings` | `smtpEnabled`, `smtpHost`, `smtpPort`, `smtpUser`, `smtpPasswordEncrypted` | Общий SMTP в настройках почты; порт по умолчанию 465, фактический берётся у почтового провайдера |
| `TechnicalSettings` | `marketingFromEmail`, `orderFromEmail`, `recoveryFromEmail`, `supportEmail` | Адреса отправителей и поддержки |
| `MailSmtpProfile` | `operation`, `enabled`, `host`, `port`, `user`, `passwordEncrypted` | Профиль конкретной операции; проверить каждый используемый профиль |
| `TechnicalSettings` | `backupReportEnabled` | Включение отчётов о резервном копировании |

Не записывайте открытый пароль SQL-командой в `smtpPasswordEncrypted`/`passwordEncrypted`: это поля шифротекста. При недействующих SMTP-доступах сайт может запускаться, но письма не будут доставляться. Проверяйте доставку на принадлежащий владельцу адрес, после согласования отправки.

### 10.2. Приём платежей

`TechnicalSettings.checkoutEnabled` - действующий переключатель «Приём платежей на сайте». Он восстановится в состоянии снимка. Изменение в админке требует права `checkout.write` и 2FA, журналируется. Сверьте состояние **до открытия сайта покупателям**.

Выключение блокирует новые платные заказы и платёжные ссылки; callback и проверка ранее начатых платежей продолжаются. Заказ с полной скидкой по промокоду может пройти без оплаты. Мастер не меняет этот флаг, платежи, возвраты или SMTP в БД.

## 11. Полная карта S3 и backup

### 11.1. Адреса хранилищ и секреты

| Хранилище | Несекретная конфигурация | Credentials | Исходные значения |
| --- | --- | --- | --- |
| Timeweb | `/root/backups/s3-config.json` | `/root/backups/s3-credentials.json` | endpoint `https://s3.twcstorage.ru`; bucket `c621752d-bf59-48fc-bc71-eaad18817ae8`; region `ru-1` |
| REG.RU | `/root/backups/regru-s3-config.json` | `/root/backups/regru-s3-credentials.json` | endpoint `https://s3.regru.cloud`; bucket `backups-gspro`; region `us-east-1` |

Регион здесь - параметр подписи S3, а не адрес сайта. Оставляйте исходный, если продолжаете использовать прежние хранилища. Другой endpoint/bucket/region допустим при фактически созданном совместимом хранилище и выданных ключах. Мастер не создаёт бакет и не проверяет доступ по сети.

Каждый credentials JSON имеет ровно поля `access_key` и `secret_key`. Их мастер спрашивает скрыто и пишет с правами 600; значение не появляется в настроенном Bash. JSON не выводите на экран и не включайте в публичные архивы инструкции.

## 12. Проверки перед публикацией

### 12.1. Сверить пять образов без вывода env

После успешного `--apply` можно выполнить эту несекретную сверку. Она ничего не скачивает:

```bash
python3 - <<'PY'
import json, subprocess
from pathlib import Path
expected = json.loads(Path('/root/gspro-setup/setup.json').read_text())['images']
for tag, image_id in expected.items():
    actual = subprocess.check_output(
        ['docker', 'image', 'inspect', '--format', '{{.Id}}', tag], text=True).strip()
    if actual != image_id:
        raise SystemExit('ID не совпал: ' + tag)
    print('OK:', tag)
PY
```

Если использовали другой `--output`, измените путь к `setup.json`. Должно быть пять `OK`: web, Mini App, bot, PostgreSQL и Caddy. Не выполняйте `docker pull`: существующий тег провайдера может уже указывать на другую сборку.

### 12.2. Проверить оба S3

```bash
python3 /root/backups/scripts/s3_store.py check
```

Актуальная версия должна проверить оба хранилища. Если одно не прошло, исправьте его конфигурацию или права ключа. Включать расписание до подтверждения обеих копий нельзя.

### 12.3. Переключить адрес и Telegram

При плановом переносе остановите приём записи на старом экземпляре, создайте финальный снимок в S3 и скачайте его на новый VPS. Не запускайте новый bot, пока старый polling-worker действует. При утрате сервера убедитесь через провайдера, что старый экземпляр не возобновится параллельно.

В DNS направьте A домена `gspro.store` на IPv4 нового VPS. AAAA должна указывать на фактически обслуживаемый IPv6 нового VPS; устаревшую AAAA удаляет владелец. Проверьте firewall провайдера: HTTPS TCP 443 и HTTP TCP 80 для сертификата/редиректа; UDP 443 используется Caddy для HTTP/3. SSH - выбранный порт. БД наружу не открывается.

**IP не заменяет production URL.** Сайт открывайте как `https://gspro.store`. В сохранённом образе этот адрес встроен в Next.js. Вход через IP, другой домен или несовпадающий Origin может приводить к «Недопустимый источник запроса». Production Caddy не должен обходить эту проверку или снимать Secure с cookie.

## 13. Запуск сайта и контроль работы

После решения владельца о переключении:

```bash
cd /opt/gspro
./deploy/dc up -d --no-build --pull never --wait
bash deploy/verify-miniapp.sh
./deploy/dc ps
```

`--pull never` запрещает подмену отсутствующих тегов загрузкой из сети. Если образ отсутствует, вернитесь к `docker load` и сверке ID. `--no-build` само по себе запрещает только сборку и не заменяет запрет pull.

Проверьте:

- HTTPS и сертификат на правильном домене, главную страницу и каталог.
- Вход владельца, 2FA, обновление сессии и выход; посторонний Origin должен по-прежнему отклоняться.
- Учётные записи сотрудников и права, включая отозванные после даты снимка.
- Telegram-группу, единственный polling-worker, кнопки и Mini App через действующего бота.
- SMTP-профили, отправителей и фактическую доставку согласованного тестового письма.
- Platega Merchant ID/secret, callback URL и расхождения оплат/возвратов после даты снимка.
- Состояние переключателя «Приём платежей на сайте» до открытия продаж.

Реальная покупка, отправка сообщения или письма - действие владельца по отдельному решению. Для проверки восстановления БД и образов проводить оплату не требуется.

После проверки платёжной конфигурации включите reconciliation:

```bash
systemctl enable --now gspro-platega-reconcile.timer
```

## 14. Проверить новую копию и включить расписание

Сначала создайте одну новую зашифрованную копию:

```bash
systemctl start gspro-backup@daily.service
systemctl show gspro-backup@daily.service -p Result -p ExecMainStatus
cat /root/backups/multi-s3-last-success.json
```

Служба должна закончиться успешно: `Result=success`, `ExecMainStatus=0`. Квитанция должна быть **свежей**, относиться к этому запуску и подтверждать оба S3. Старая квитанция из снимка не является доказательством новой выгрузки.

Проверьте наличие нового снимка, опубликованного recovery-kit, checksum и защищённого ключа в обоих хранилищах. Recovery-kit при публикации получает актуальные configs и обновлённый downloader. Не помещайте S3 credentials или открытый приватный ключ в `recovery-kit/`: publisher для них не предназначен.

Только после успеха обоих назначений:

```bash
systemctl enable --now \
  gspro-backup-recover.service \
  gspro-backup-daily.timer \
  gspro-backup-monthly.timer \
  gspro-backup-notify.timer \
  gspro-backup-watchdog.timer
systemctl list-timers 'gspro-*'
```

Проверьте уведомление владельцу и следующие срабатывания. При сбое одного S3 локальные копии могут сохраняться для повторной выгрузки; контролируйте диск. Настройте внешний мониторинг нового IP отдельно: разрешение порта 10050 в UFW ещё не устанавливает агент и не создаёт проверку в панели провайдера.

## 15. Оставшиеся параметры, которые нельзя получить из архива автоматически

1. **IP нового сервера и DNS A/AAAA** - ввод и настройка владельцем; мастер спрашивает IP, DNS сам не меняет.
2. **Публичный SSH-ключ, SSH port и firewall провайдера** - ключ/порт спрашиваются; панель провайдера отдельно.
3. **Доступы обоих S3** - обязательный скрытый ввод; ключи намеренно не входят в recovery-kit.
4. **Пароль encrypted PEM** - отдельный скрытый ввод при расшифровке; без него полный снимок не открыть.
5. **Действительность SMTP, Platega и Telegram** - значения восстановятся, но внешний доступ мог измениться; проверить кабинеты и UI.
6. **Menu Button/Mini App URL и username при смене бота** - отдельная настройка в Telegram.
7. **Доступность закреплённых apt-пакетов** - фактическая проверка на новом сервере; мастер не проверяет репозитории.
8. **Состояние продаж, сотрудники, 2FA, оплаты/возвраты после снимка** - сверка владельцем; snapshot фиксирует прошлое состояние.
9. **Мониторинг и время таймеров** - проверить на новом VPS; JSON-календарь не меняет systemd автоматически.
10. **Другой домен** - этот комплект его не поддерживает простой заменой переменной; нужны пересборка и отдельные проверки Origin/cookie/HTTPS.

## 16. Типовые остановки и действия

| Сообщение / симптом | Что проверить |
| --- | --- |
| Нужен Ubuntu 24.04 / root | ОС, архитектуру и пользователя; `sudo -i` на предназначенном новом VPS |
| Скрытый ввод / TTY недоступен | Запустить в обычном интерактивном SSH-терминале; не передавать секрет через stdin или параметр команды |
| Каталог результата уже существует | Новый `--output`; прежние материалы сохранить для проверки |
| SHA256 не совпал / manifest не покрывает файл | Получить полный исходный комплект; не исправлять hashes вручную |
| Другой домен / production preflight | Использовать проверенный gspro.store и исходные подтверждения; другой домен требует отдельной сборки |
| Оригинальное значение не совпало | Не менять crypto/DB/session keys; сравнить выбранный snapshot с уже восстановленным сервером |
| Deployment / backup выполняется | Дождаться завершения, затем повторить применение; не обходить flock |
| Публичные службы уже запущены | Для первоначального применения оставить только DB; состояние и остановку служб проверить до повторного действия |
| Частично выполненный apply / previous-config | Не запускать повторную запись автоматически; проверить резервные файлы и сообщение rollback |
| apt не находит закреплённую версию | Проверить репозиторий и совместимость нового набора; не удалять данные ради повторного installer |
| «Недопустимый источник запроса» | Канонический HTTPS-домен, DNS, встроенный NEXT_PUBLIC_SITE_URL и Origin; сохранить штатную проверку источника запроса |
| Бот получает конфликт polling | Найти и остановить прежний экземпляр; новый worker должен быть единственным |
| Письма не приходят | SMTP в админке, профили, пароль, отправители, доступность провайдера; EMAIL_API env не заменяет SMTP из БД |
| S3 check или backup не прошёл | Оба endpoint/bucket/region, credentials, права List/Get/Put/Delete, префикс и свежая квитанция |

## 17. Что проверено при выпуске этого пакета

- Восемь проверок начального `fetch-recovery-kit.py`: правильные два объекта, SHA256, неверный checksum, несовпадение размера, лимит архива, запрет перезаписи, откат сохранения пары файлов и отказ от открытого ввода ключей. S3-клиент имитировался; проверка путей/прав Ubuntu проведена статически.
- 27 автоматических проверок на синтетических снимках и ключах: manifests, небезопасные пути, неизменяемые значения, редактирование и runtime, скрытый ввод, применение/отказ/отмена, rollback.
- Синтаксис настроенного установщика проверен настоящим Bash из сохранённого образа PostgreSQL. Установщик не исполнялся.
- Четыре строки с `$`, `#`, кавычками, пробелами и обратной косой чертой прошли через Docker Compose в фактическое окружение временного контейнера без изменений. Использовался сохранённый образ, сеть отключена, pull запрещён, реальные секреты не участвовали.
- Выполнена независимая статическая проверка карты конфигурации и защит мастера; замечания о manifests, ключах, блокировках, путях и откате исправлены.

На VPS эти настройки при выпуске пакета не применялись. Полная установка на свежем Ubuntu VPS, наличие apt-версий, реальная конкуренция Linux flock, доступность SMTP/Telegram/Platega и новые выгрузки S3 этим выпуском не проверялись. В тестах файловой логики `--apply` Linux root/права и Docker status имитировались; особенности POSIX прав проверены статически. Отчёт `Проверка_мастера.json` содержит эти границы.

После серверной проверки храните исходный snapshot, encrypted key и приватную папку настройки в защищённом месте владельца. Архив `GSPro-Server-Setup.zip` содержит только мастер, начальный загрузчик, инструкции, отчёт и hashes; реальные env, S3-credentials, БД и приватные ключи в него не входят.
