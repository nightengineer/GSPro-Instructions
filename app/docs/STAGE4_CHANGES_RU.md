# GSPro Stage4 — админка и покупки

Историческое описание этапа. Для работы с текущим production используйте `/opt/gspro/README/00_Начать_здесь.md`; тестовые режимы этого этапа не отражают состояние рабочего сайта.

Владелец: owner@example.test, пароль — заданный владельцем при создании Stage4. Пароль в файлах не хранится.

## Запуск

Эксплуатация текущего сайта описана в `/opt/gspro/README/00_Начать_здесь.md`.

## Что доступно владельцу

- Роли SUPER_ADMIN («Главный администратор») и ADMIN («Администратор») допускаются в админку. Обычный пользователь не видит пункт, адрес страницы отдаёт 404, API проверяют роль на сервере. Изменения пишутся в журнал аудита. Самостоятельное назначение ролей через регистрацию невозможно.
- Каталог: добавление игры через плюс, название, адрес, издатель, изображение, валюта, порядок, видимость. Неактивные игры прежних этапов открываются кнопкой «Показать скрытые» и не показываются покупателям.
- В каждой игре — любое число шагов оплаты (до 20), со ссылками, сортировкой и удалением. Шаги перенесены с главной в выбор пополнения.
- Наборы (до 60): название, количество, цена в рублях до комиссии, комиссия 0–100%, изображение, доступность и порядок. Можно загружать PNG/JPG/WebP до 2 МБ или выбрать иллюстрации сундука, алмаза, реактора. Загрузки хранятся в базе и сохраняются при перезапуске.
- Своё количество: включение/отключение, минимум, максимум, шаг, курс в копейках за единицу и комиссия. Диапазон должен делиться на шаг; лимиты итоговой суммы проверяются сервером.
- Настройки сайта: редакторы пяти документов, произвольные поля реквизитов и контактов, адреса отправителей восстановления/рассылки/заказов и поддержки, карусель с добавлением, порядком, видимостью, изображениями, текстами и ссылками слайдов.
- Изменённый документ получает новую редакцию; предыдущие редакции сохраняются в базе. Заказы и согласия ссылаются на принятые версии.
- Промокоды: процент 1–100%, код из 3–32 латинских букв, цифр и дефисов. Таблица показывает доступность, использование и связанный заказ. Неиспользованный код можно отключить. Использованный повторно не активируется.

## Что изменилось для покупателя

- Наборы показывают иллюстрации и полную цену с комиссией. В окне игры находятся её собственные шаги оплаты и отзывы с оценкой 1–5, именем автора и купленным товаром.
- В кабинете у заказа есть кнопка отзыва. Публикация разрешена владельцу оплаченного, выполняемого или выполненного заказа; один отзыв на заказ. Администратор может удалить отзыв прямо из окна игры.
- Количество в проверке заказа фиксировано. Сервер проверяет подписанный выбор товара, пользователя, актуальную цену и версии документов; изменение полей запроса не позволяет изменить покупку. Проверка действует 30 минут.
- Промокод применяется кнопкой до оформления и сразу меняет итог. Код расходуется при создании заказа (в том числе до оплаты), а не при предварительной проверке. При одновременном использовании проходит только один заказ. Скидка 100% создаёт оплаченный заказ без обращения к платёжному провайдеру.
- В чате появилось приветствие помощника и кнопка «Статус заказа», которая читает текущий статус выбранного заказа. Чаты других пользователей недоступны.
- Акции недели стали настраиваемой каруселью. Первый слайд ведёт в Telegram за промокодом к открытию. Добавлено обозначение USDT. Внизу — запрошенный блок «Почему нас выбирают».

## Границы этого этапа

Локальная версия сохраняет существующий демонстрационный режим платежей. USDT добавлен в оформление, но отдельный криптопроцессинг не подключён. Для реальной оплаты нужны настройки провайдера. Реальные письма требуют подключённого почтового сервиса и подтверждённых адресов отправителей; локально восстановление использует тестовый почтовый ящик. Поле рассылок сохраняет адрес отправителя, редактор и запуск рассылок относятся к следующей доработке. Интерфейс управления ролями не добавлялся.

## Проверки

```powershell
docker exec gsprostage4-web-1 npm run check
```

В scripts/stage4-verify.cjs — сквозная проверка API и браузера. Нужны Node, Playwright, Edge, запущенный контейнер и пароль владельца в переменной STAGE4_OWNER_PASSWORD; пароль нельзя вписывать в файл. Путь к модулю Playwright задаётся PLAYWRIGHT_MODULE при необходимости. Проверка создаёт и удаляет временные аккаунты, игры, заказы, изображения и промокоды; временно меняет настройки и затем восстанавливает их. Запускать на локальной тестовой копии без одновременного редактирования администратором. Журнал аудита и версии документов сохраняются.

Результат: artifacts/stage4-verification.json. Список отличий от Stage3: artifacts/stage4-file-changes.json. Скриншоты artifacts/stage4-*.png включают временные проверочные данные.
