# Изменения GSPro — этап 1, 7 сентября 2026

Историческое описание этапа. Для работы с текущим production используйте `/opt/gspro/README/00_Начать_здесь.md`; тестовые режимы этого этапа не отражают состояние рабочего сайта.



## Что изменено

- Главная получила короткий адрес `/gspro`; `/` сохранён. Демо-покупки находятся под баннером на всю его ширину. Обновлены тексты баннера, четыре шага пополнения, безопасность и ссылка на Telegram.
- В каталоге Last Empire – War Z, Fate War, Tiles Survive!. Старые игры выключены в БД, чтобы сохранить ссылки исторических заказов. Картинки загружены с официальных ресурсов издателей.
- При выборе игры открывается диалог поверх страницы с уведомлением об обязательной регистрации, фиксированными товарами (3 / 2 / 1), ползунком отдельного варианта и подсветкой выбранного товара. После выбора активируется переход к оформлению.
- Сервер допускает оформление только из действующего аккаунта. После регистрации или входа открывается ранее выбранный товар. Цена и количество фиксированного товара берутся с сервера; подмена полей браузером не меняет сумму. В заказ записываются ID и название товара, количество и снимок цены.
- На страницах авторизации убраны поиск и кнопка входа из шапки, добавлена кнопка на главную. В формах есть восстановление доступа по шестизначному коду.
- В кабинете заказы расположены отдельными карточками в центральной колонке. Справа — закреплённый чат; выбранный заказ соединяется с ним подсвеченной линией. Пока грузится переписка, мерцает иконка стрелок. На телефоне чат открывается на весь экран с возвратом к выбранному заказу.
- Сообщения сохраняются в PostgreSQL отдельно для заказа. Пользователь получает доступ только к своим заказам. Переписка обновляется каждые 5 секунд. Добавлен API ответа администратора с проверкой роли и аудитом. Интерфейс оператора будет доработан вместе с админкой.
- На аккаунте `owner@example.test` добавлены 9 тестовых заказов: шесть фиксированных товаров и по одному произвольному пополнению каждой игры (20 000–100 000). Показаны все восемь существующих статусов заказа. Тестовые заказы явно помечены и защищены от повторной оплаты.
- Из шапки кабинета убран поиск; выход требует подтверждения в диалоге в стиле сайта.

## Почта и восстановление доступа

`POST /api/auth/recovery` принимает `action: request` (email) или `action: reset` (email, code, password). Обе операции защищены CSRF. Код создаётся криптографическим генератором, в БД хранится HMAC, срок действия — 10 минут, максимум 5 неверных попыток, повторная отправка — не чаще раза в минуту. Блокировка строки пользователя защищает операции от одновременного использования кода. Смена пароля потребляет код и повышает версию сессий; старые сессии больше не действуют.

В локальном Docker-профиле включён тестовый почтовый адаптер. **Настоящие письма не отправляются**; форма прямо сообщает об этом. Коды не выдаются через API и не печатаются в логах. Тестовое письмо сохраняется только внутри контейнера в `/tmp/gspro-mail/`, что позволяет проверять сценарий без внешней рассылки. Проверочные письма удаляются тестовым скриптом.

Для реальной доставки задать `EMAIL_API_URL`, `EMAIL_API_TOKEN` и адрес отправителя в `TechnicalSettings.recoveryFromEmail` (строка `id=main`); резервный вариант — `EMAIL_FROM`. Убрать `RECOVERY_MAIL_MODE=local` и `ALLOW_LOCAL_TEST_DATA=true`. Адаптер отправляет POST JSON `{from,to,subject,text}` с Bearer-токеном, совместимо с существующим почтовым шлюзом проекта. Адрес отправителя должен быть подтверждён у выбранного провайдера. Адреса почты для технических функций заложены в `TechnicalSettings`; их формы настройки будут частью будущей админки. Реальная доставка через почтовый сервис пока не проверена: доступы не предоставлены.

## Основа для следующих этапов

Новые таблицы: `Product`, `PasswordReset`, `TechnicalSettings`, `OrderMessage`. У `Game` появились `imageUrl`, `customEnabled`; у заказа — снимок товара и признак тестовых данных; у пользователя — версия сессий. Миграция `20260907000000_stage1_catalog_recovery_chat` добавляет поля без удаления прежних заказов и аккаунтов.

Фиксированные номиналы и цены сейчас тестовые, единица названа «игровой валюты». Перед реальными продажами в админке нужно утвердить названия валют, номиналы, цены и условия доставки. Таблицы позволяют редактировать игры, изображения, доступность и товары без изменения компонентов. Новые товары подхватываются витриной из БД. Веб-админка целиком на этом шаге не переделывалась.

`GET/POST /api/orders/:id/messages` — переписка покупателя; `GET/POST /api/admin/orders/:id/messages` — просмотр и ответ администратора. Ответы администратора записывают аудит `ORDER_CHAT_REPLY`. Изменения статусов и расширенные инструменты операторов остаются частью будущей админки.

Документ P0 в исходном проекте не изменялся: незакрытые вопросы ТЗ не помечались согласованными автоматически.

## Проверки

- `npm run check`: проверка исходников и 9 тестов цены, шифрования и подписей.
- `prisma validate`: схема корректна.
- `npm run build`: production-сборка приложения.
- `scripts/stage1-api-test.mjs`: 9 групп проверок — регистрация, блокировка гостевой покупки, неподменяемая цена, чужие товары, диапазон количества, разграничение доступа к чату, сохранение сообщений, ответ администратора с аудитом, восстановление пароля, отзыв сессий, повторное использование/истечение/лимит попыток кода.
- `scripts/stage1-browser.cjs`: каталог 3 / 2 / 1, выбор товара, переход через регистрацию, кабинет, закрепление чата, мобильная версия 390 px, отмена выхода. Скриншоты и JSON-отчёты — `artifacts/stage1-*`.

Унаследованная БД имеет различие `ON UPDATE` у внешних ключей старых таблиц относительно Prisma-схемы. Оно существовало до этой доработки; новые таблицы соответствуют миграции. Поведение старых связей не менялось.
