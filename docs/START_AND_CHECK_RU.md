# Запуск и проверка GSPro после сбоя

На существующем VPS из папки установленного сайта:

```bash
cd /opt/gspro
sudo bash deploy/start-and-check.sh
```

Скрипт при необходимости запускает Docker, находит контейнеры текущего Compose-проекта и запускает остановленные: PostgreSQL, сайт, Mini App, бот, Caddy. Ожидает `healthy` у первых четырёх, `running` у Caddy, затем проверяет публичные HTTPS `/api/health` (включая базу) и страницу `/tg-admin`; состояние базы Mini App проверяет внутри её контейнера через `/tg-admin/api/health` (этот endpoint штатно закрыт снаружи). Успех — сообщение `SUCCESS` и код выхода 0; ошибка — код 1 и состояния контейнеров. Секреты и журналы приложения не печатаются.

```bash
# Только проверка, без запуска Docker и контейнеров:
sudo bash deploy/start-and-check.sh --check-only
# До 10 минут ожидания КАЖДОГО сервиса:
sudo bash deploy/start-and-check.sh --timeout 600
# Только если бот намеренно не установлен/отключён:
sudo bash deploy/start-and-check.sh --without-bot
```

Поддерживаются единый `compose.yaml` и production-комплект с `compose.telegram.yaml`, `compose.miniapp.yaml`, `.env.telegram`. По умолчанию корень проекта определяется относительно скрипта; можно задать `sudo GSPRO_APP_ROOT=/opt/gspro bash /путь/start-and-check.sh`.

Нужны Bash, Docker с Compose plugin, curl, Python 3, flock; целевая ОС — Ubuntu VPS. Файлы `.env` и существующие контейнеры должны быть на сервере. Для работы скрипта нужен уже установленный сервер с восстановленными конфигурациями.

Скрипт использует блокировку действующего резервирования `/run/lock/gspro-backup.lock`. Если копирование/восстановление занято, завершится с ошибкой: повторите после завершения. Не запускайте параллельно с деплоем или ручным восстановлением. Повторный запуск допустим, работающие контейнеры не перезапускаются. Миграции, пересборка, пересоздание контейнеров, удаление томов и импорт старого бэкапа не выполняются. Отсутствующий обязательный контейнер — ошибка до запуска остальных.

После потери контейнеров или диска сначала используйте инструкции восстановления. На новом VPS не запускайте копию бота одновременно со старым сервером. Healthcheck бота и HTTP не заменяют проверку реального сообщения Telegram, письма SMTP или оплаты. Ошибки DNS/сертификата/внешней сети также приводят к ошибке проверки HTTPS. Скрипт запускается вручную и не устанавливает автозапуск или мониторинг.

Сверено с локальным снимком исходников 27.09.2026; запуск на VPS в этой актуализации не выполнялся. Команда использует Docker Compose напрямую, поэтому не вызывает deploy/dc, не обновляет .env.runtime и не применяет новые env. Блокировка резервирования не заменяет .deploy.lock; отсутствие параллельного деплоя обеспечивает администратор.
