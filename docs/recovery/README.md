# Восстановление GSPro: что найдено на VPS и S3

Проверка выполнена 28.09.2026 через чтение VPS, REG.RU и Timeweb. Сервер и объекты S3 не изменялись.

## Начать с самого простого способа

Для нового пустого Ubuntu 24.04 x86_64 используйте [интерактивный мастер](../../server-setup/Инструкция_настройки_GSPro.md). Он уже использует установщик из актуального S3-комплекта и дополнительно проверяет пути, ключи и образы, опрашивает настройки и применяет их с блокировками и откатом.

Если нужен ручной независимый путь при полной потере VPS, используйте [новую инструкцию восстановления из S3](Восстановление_из_S3.md), [PDF](Восстановление_из_S3.pdf). Старый VPS для этого не нужен: достаточно собственных S3-доступов, пароля ключа восстановления, DNS и нового сервера.

## Где что лежит

| Место | Что обнаружено | Применение |
|---|---|---|
| Оба S3: `gspro/recovery-kit/` | README, downloader, CMS-расшифровщик, installer, restore, backup-system и контрольные суммы | Независимое восстановление нового VPS |
| VPS: `/root/backups/recovery-kit/` | README и четыре основных инструмента совпадают с S3 | Источник независимого комплекта |
| VPS: `/opt/gspro/Восстановление/` | Пять инструкций и три инструмента | Справка; installer здесь старее S3-версии |
| VPS: `/opt/gspro/docs/production/Восстановление/` | Эксплуатационные инструкции восстановления | Уже скопированы в этот публичный репозиторий |
| VPS: `/root/backups/scripts/recover.py` | Запуск контейнеров, остановленных прерванным резервированием | Служебное возобновление контейнеров; данные из архива не восстанавливает |

Оба S3-архива recovery-kit побайтно одинаковы, содержат 16 файлов. SHA256: `7e29c8f10bef1d2f6425453d8955fb01db51ac54790092d9d509ea2c4b5b2110`.

Последний daily в обоих S3: 27.09.2026, 621 015 425 байт; ключ `gspro/backups/daily/2026-09-27.tar.gz--37eea17730ba1e05.cms`. Полный daily здесь заново не скачивался: проверены его ключ, размер и дата. Recovery-kit скачан из каждого S3 полностью и сверён по SHA256.

На дату проверки REG.RU содержит один daily, без monthly/pre-release; Timeweb - четыре daily, один monthly и один pre-release. Для старой контрольной точки нужно выбрать Timeweb и нужный вид копии; downloader показывает доступные даты.

## Какие средства актуальнее

Installer из S3 совпадает с версией, которую использует наш мастер. Он новее `/opt/gspro/Восстановление/deploy-new-vps.sh`: добавлены поддержка второго S3 для соответствующих прежних снимков, recovery-kit и обновлённые уведомления. Поэтому актуальный исходник для нового сервера берётся из полного независимого S3-комплекта.

Расшифровщик и restore на VPS и в S3 совпадают. Полный installer запускает `deploy/restore.sh` из восстановленного приложения: отдельная копия `tools/restore.sh` полезна для проверки порядка, но сама не подменяет скрипт внутри снимка.

## Опубликованная часть и поправки

- [Downloader](download-backup.py) и [restore](tools/restore.sh) совпадают с S3.
- [Расшифровщик](tools/decrypt-cms-stream.py) дополнен запретом открытого ввода пароля, если терминал не поддерживает скрытый ввод.
- [Installer](tools/deploy-new-vps.sh) допускает только `START_PUBLIC_SERVICES=false`: запуск сайта, бота и таймеров выполняется отдельно после проверки.
- [Пакет инструментов](../../GSPro-Recovery-Tools.zip) и [SHA256](../../GSPro-Recovery-Tools.zip.sha256) содержат только четыре инструмента, краткую инструкцию и контрольные суммы. Для установки нужен полный закрытый kit из S3, включая `backup-system/`.
- [Сверка исходников](Проверка_источников.json) содержит SHA256 и результаты ограниченных испытаний.

Защищённый приватный PEM, сертификат, configs конкретного хранилища, credentials, дампы и образы в эту публикацию не включены. Публичные поправки не установлены на VPS или S3. Полное развёртывание на чистом Ubuntu этой проверкой не выполнялось.
