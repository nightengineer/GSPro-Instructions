# GSPro: независимое восстановление из S3

Ubuntu 24.04 x86_64. Редакция 28.09.2026. Полный старый VPS для этого способа не нужен.

## 1. Самый простой способ

Используйте [интерактивный мастер настройки](https://github.com/nightengineer/GSPro-Instructions/blob/main/server-setup/Инструкция_настройки_GSPro.md). Он получает тот же актуальный recovery-kit и опрашивает адрес нового сервера, доступы и настройки. В инструкции перечислены все файлы и переменные.

Далее описан ручной запасной путь, основанный на проверенной инструкции S3. Он требует заполнить параметры установщика и секретные файлы самостоятельно. Все команды выполняются на новом пустом Ubuntu VPS в SSH-терминале с root-доступом и доступной консолью провайдера.

## 2. Что подготовить

| Данные | Где получить |
|---|---|
| Доступы List/Get нужного S3 | Панель владельца REG.RU или Timeweb |
| Пароль защищённого ключа восстановления | Отдельное хранилище паролей владельца |
| Новый публичный IP сервера | Панель нового VPS |
| Публичный SSH-ключ владельца | Файл `.pub`; приватный ключ остаётся у владельца |
| Доступ к DNS `gspro.store` | Панель владельца домена |
| Новые credentials двух S3 для регулярных копий | List/Get/Put/Delete в префиксах GSPro |

Используйте собственные доверенные архивы GSPro. SHA256 проверяет совпадение с контрольной суммой; архив и checksum из одного источника сами по себе не удостоверяют автора. CMS AES-GCM проверяет целостность зашифрованных данных. Распаковка и запуск выполняются с root-доступом, поэтому источник должен быть доверенным.

Сохранённые образы рассчитаны на `gspro.store`. Другой домен требует проверенной отдельной сборки. Для последнего снимка 27.09.2026 оставьте `RELEASE_VARIANT` пустым: в нём один комплект приложения и пять образов.

## 3. Получить полный kit из S3

Подготовьте Python и инструменты распаковки. Эти команды устанавливают программы на новый VPS:

```bash
apt-get update
apt-get install -y python3 python3-boto3 python3-cryptography \
  openssl ca-certificates curl unzip
umask 077
install -d -m 700 /root/gspro-server-setup /root/gspro-recovery
GSPRO_DOCS_URL=https://raw.githubusercontent.com/nightengineer/GSPro-Instructions/main
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip" \
  -o /root/GSPro-Server-Setup.zip
curl -fL "$GSPRO_DOCS_URL/GSPro-Server-Setup.zip.sha256" \
  -o /root/GSPro-Server-Setup.zip.sha256
cd /root
sha256sum -c GSPro-Server-Setup.zip.sha256
unzip -n GSPro-Server-Setup.zip -d /root/gspro-server-setup
cd /root/gspro-server-setup
sha256sum -c SHA256SUMS
python3 fetch-recovery-kit.py
```

Выберите REG.RU или Timeweb. Введите endpoint, bucket, регион и скрыто Access/Secret Key. Для REG.RU стандартные параметры уже предложены; для Timeweb укажите свой bucket. Ключи остаются в памяти загрузчика. Путь назначения оставьте `/root/gspro-recovery`.

```bash
cd /root/gspro-recovery
sha256sum -c recovery-kit.tar.gz.sha256
tar -xzf recovery-kit.tar.gz
cd recovery-kit
sha256sum -c MANIFEST.sha256
```

В полном закрытом kit находятся также `backup-system/` и защищённый ключ. Его публичная копия инструментов ниже не заменяет эти файлы. Пароль защищённого PEM в S3 не хранится.

## 4. Подготовить проверенную рабочую копию инструментов

Публичная редакция исправляет два места: расшифровщик запрещает открытый ввод пароля вне TTY, установщик запрещает автоматический публичный запуск. Оригинальный kit сохраните без правок. Создайте новую рабочую копию и примените к ней проверенные инструменты:

```bash
cd /root
GSPRO_DOCS_URL=https://raw.githubusercontent.com/nightengineer/GSPro-Instructions/main
curl -fL "$GSPRO_DOCS_URL/GSPro-Recovery-Tools.zip" \
  -o GSPro-Recovery-Tools.zip
curl -fL "$GSPRO_DOCS_URL/GSPro-Recovery-Tools.zip.sha256" \
  -o GSPro-Recovery-Tools.zip.sha256
sha256sum -c GSPro-Recovery-Tools.zip.sha256
test ! -e /root/gspro-reviewed-tools
install -d -m 700 /root/gspro-reviewed-tools
unzip -n GSPro-Recovery-Tools.zip -d /root/gspro-reviewed-tools
cd /root/gspro-reviewed-tools
sha256sum -c SHA256SUMS
test ! -e /root/gspro-recovery/recovery-kit-reviewed
cp -a /root/gspro-recovery/recovery-kit \
  /root/gspro-recovery/recovery-kit-reviewed
cp download-backup.py /root/gspro-recovery/recovery-kit-reviewed/
cp tools/*.py tools/*.sh /root/gspro-recovery/recovery-kit-reviewed/tools/
```

После замены двух инструментов старый `MANIFEST.sha256` относится к исходному kit; не используйте его для сверки изменённой рабочей копии. SHA256 публичных инструментов проверен отдельно перед копированием. Installer по-прежнему видит полный `backup-system/` рядом с `tools/`.

## 5. Скачать выбранный снимок и расшифровать

```bash
cd /root/gspro-recovery/recovery-kit-reviewed
python3 download-backup.py regru --kind daily \
  --output /root/gspro-recovery/downloaded
cd /root/gspro-recovery/downloaded
sha256sum -c snapshot.cms.sha256
python3 ../recovery-kit-reviewed/tools/decrypt-cms-stream.py \
  snapshot.cms private.encrypted.pem snapshot.tar.gz
test ! -e /root/restore-prod11
mkdir -m 700 /root/restore-prod11
tar -xzf snapshot.tar.gz -C /root/restore-prod11
cd /root/restore-prod11
sha256sum -c SHA256SUMS
```

Downloader скрыто запросит S3-ключи и покажет даты доступных снимков; расшифровщик отдельно запросит пароль PEM. При ошибке SHA256 или GCM остановитесь. Не используйте частичный вывод, не перезаписывайте прежние каталоги.

Для Timeweb замените `regru` на `timeweb`. Для старой контрольной точки используйте `--kind monthly` или `--kind pre-release`. На дату сверки в REG.RU есть только один daily; в Timeweb также есть исторические копии. Выберите снимок до повреждения данных, а не просто самый новый.

Downloader получает текущий защищённый PEM. Если сам ключ менялся, старый снимок требует соответствующей сохранённой версии из `gspro/recovery-keys/`; автоматического выбора старого ключа нет. Смена только пароля защиты не меняет сам приватный ключ.

## 6. Заполнить параметры нового сервера

Сохраните публичный ключ владельца в `/root/owner-public-key.pub`, завершите ввод Ctrl+D и проверьте отпечаток:

```bash
cat > /root/owner-public-key.pub
chmod 600 /root/owner-public-key.pub
ssh-keygen -lf /root/owner-public-key.pub
```

Редактируйте только рабочий `/root/gspro-recovery/recovery-kit-reviewed/tools/deploy-new-vps.sh`. Таблица параметров:

| Переменная | Значение |
|---|---|
| `NEW_SERVER_IP` | Новый публичный IP VPS; заменить `CHANGE_ME` |
| `DOMAIN` | `gspro.store` для сохранённых образов |
| `APP_ROOT` | `/opt/gspro` |
| `SNAPSHOT_DIR` | `/root/restore-prod11` |
| `SSH_PORT` | Порт SSH нового сервера, обычно `22` |
| `SSH_PUBLIC_KEY_FILE` | `/root/owner-public-key.pub` |
| `DOCKER_IMAGE_ARCHIVE` | `$SNAPSHOT_DIR/images.tar.gz`, оставить загрузку сохранённых образов |
| `START_PUBLIC_SERVICES` | Только `false`; публичная редакция откажет при `true` |
| `RELEASE_VARIANT` | Для последнего полного снимка не задавать |
| Версии Docker/Compose/containerd/buildx | Сверить с `host-packages.txt` и доступными совместимыми пакетами |

Installer ставит Docker, меняет SSH/UFW/fail2ban/обновления и swap, устанавливает выбранные GSPro units. Запуск требует решения владельца нового VPS. Сохраните консоль провайдера и проверьте новый SSH-вход до закрытия старого терминала. Чужие host keys, дисковые IDs и весь старый `/etc` не копируются.

## 7. Восстановить без запуска сайта и бота

```bash
cd /root/gspro-recovery/recovery-kit-reviewed
bash -n tools/deploy-new-vps.sh
bash tools/deploy-new-vps.sh
```

Installer загружает сохранённые образы, восстанавливает пустую PostgreSQL и SQLite, создаёт ограниченную runtime-роль. Восстановление данных выполняет `deploy/restore.sh` из восстановленного приложения. При наличии штатной очистки завершённых заказов она тоже выполняется; количество зашифрованных паролей таких заказов может уменьшиться.

Сайт, Mini App, бот и расписание копий остаются остановленными. Сверьте ID образов с `images.json`, выполните проверки БД и ключей. Не делайте `docker pull` вместо сохранённых образов. После частичного сбоя продолжайте конкретный незавершённый шаг; повторный полный installer не возобновляет установку автоматически.

## 8. Заполнить файлы и провести переключение

Все переменные `.env`, `.env.telegram` и S3-config перечислены в [основной инструкции, разделы 8-11](https://github.com/nightengineer/GSPro-Instructions/blob/main/server-setup/Инструкция_настройки_GSPro.md). Исходные ключи приложения сохраняются из снимка, иначе прежние зашифрованные данные станут недоступны.

Создайте credentials с правами 600: `/root/backups/s3-credentials.json` для Timeweb и `/root/backups/regru-s3-credentials.json` для REG.RU. Формат: `{"access_key":"...","secret_key":"..."}`. Заполняйте защищённым вводом или редактором без swap/backup-файлов. Пароли не помещайте в командную строку или историю shell.

```bash
python3 /root/backups/scripts/s3_store.py check
```

Проверьте оба S3, SMTP, Telegram, Platega callback и состояние «Приём платежей на сайте». При полной потере VPS убедитесь, что старый сервер не возобновит работу; при плановом переносе остановите старых писателей и получите финальный снимок. Защита от одновременной работы двух ботов требует отдельного решения владельца.

Направьте DNS A/AAAA на новый VPS; уберите устаревшую AAAA, если IPv6 не обслуживается. После закрытых проверок и решения о переключении:

```bash
cd /opt/gspro
./deploy/dc up -d --no-build --wait
bash deploy/verify-miniapp.sh
./deploy/dc ps
systemctl enable --now gspro-platega-reconcile.timer
systemctl start gspro-backup@daily.service
systemctl show gspro-backup@daily.service -p Result -p ExecMainStatus
cat /root/backups/multi-s3-last-success.json
```

Только после успешной новой копии и подтверждения квитанции обоих S3:

```bash
systemctl enable --now gspro-backup-recover.service \
  gspro-backup-daily.timer gspro-backup-monthly.timer \
  gspro-backup-notify.timer gspro-backup-watchdog.timer
```

Проверьте HTTPS, вход владельца, каталог, Mini App, один Telegram-бот, SMTP, callback и служебное уведомление о копии. Новые реальные оплаты для технической проверки требуют решения владельца. Внешний мониторинг нового VPS настраивается отдельно.

## 9. Что подтверждено этой сверкой

Recovery-kit из REG.RU и Timeweb скачаны полностью, их SHA256 совпала. README и четыре основных исходника совпали с `/root/backups/recovery-kit` на VPS. S3 installer содержит поддержку зеркалирования, отсутствующую в более старой папке `/opt/gspro/Восстановление`.

Публичные исправления проходят ограниченные испытания расшифровки и проверки синтаксиса; результаты перечислены в [отчёте сверки](https://github.com/nightengineer/GSPro-Instructions/blob/main/docs/recovery/Проверка_источников.json). Полное развёртывание на новом Ubuntu VPS, доступность закреплённых apt-пакетов, DNS/HTTPS, SMTP, Telegram, платежи и новая выгрузка в оба S3 этим действием не проверены.

Публичные поправки не устанавливались на VPS или S3. Защищённый PEM, configs, дампы и образы получают только из своего закрытого хранилища.
