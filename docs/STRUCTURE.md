# Структура GSPro

Техническая карта исходников | Сверка с локальным снимком VPS: 27 сентября 2026

## 1. Состав системы

GSPro состоит из публичного магазина, веб-админки, Telegram Mini App и Telegram-бота. Web и Mini App работают с одной PostgreSQL. Caddy принимает HTTPS и направляет запросы по пути. Бот обращается к внутреннему API Mini App; служебные API не доступны через публичный прокси.

```text
Покупатель / сотрудник
        |
   HTTPS :443
        |
      Caddy
        |-- /             --> web :3000
        |-- /tg-admin     --> telegram-admin :3000
        |                         |
        +-------- PostgreSQL :5432

Telegram API <--> telegram-bot --> internal API Mini App
                      |
                SQLite /data
```

Контейнер migrate запускается на время применения миграций и завершается. Долговременные сервисы используют restart: unless-stopped; вручную остановленный контейнер может требовать отдельного запуска. [Порядок запуска и проверки](START_AND_CHECK_RU.md). Внешние зависимости: DNS, удостоверяющий центр HTTPS, Platega, SMTP/почтовый сервис и Telegram. Отказ любого внешнего сервиса проверяется отдельно от здоровья PostgreSQL.

У магазина также есть устанавливаемая веб-версия (PWA). [Ссылка установки - https://gspro.store/](https://gspro.store/): открыть в Chrome на Android и выбрать установку в меню браузера. Это тот же web-компонент, открываемый через иконку в отдельном окне; отдельного Android backend или APK в проекте нет. Telegram Mini App - самостоятельный административный компонент, её не следует путать с установленным приложением магазина.

На iPhone эта же веб-версия добавляется через Safari: «Поделиться» → «На экран “Домой”» → «Добавить»; переключатель открытия как веб-приложения включается, если показан. Отдельного iOS-проекта нет. Сквозная проверка GSPro на реальном iPhone пока не выполнена.

PWA описана в `app/app/manifest.js` и доступна по `/manifest.webmanifest`: name, short_name, icons, start_url, display, theme_color, background_color. Используется display=standalone. Отдельный service worker, офлайн-режим и push-уведомления не реализованы. При смене домена меняется и адрес установки; старая установленная копия продолжает обращаться к старому домену.

## 2. Страницы и сценарии

| Путь | Назначение |
| --- | --- |
| `/` | Главная, каталог, предложения и переходы к покупке. |
| `/games/[slug]` | Страница игры, наборы и доступные варианты количества. |
| `/checkout` | Оформление заказа, согласия, переход к оплате. |
| `/order/success` | Страница результата. Сам переход по URL не доказывает оплату. |
| `/auth/register`, `/auth/login` | Регистрация с подтверждением email; вход с обязательным вторым фактором для сотрудников. |
| `/auth/recovery` | Восстановление доступа с использованием настроенной почты. |
| `/account` | Аккаунт, покупки, сообщения, уведомления, почтовые предпочтения, безопасность и запрос удаления. |
| `/support` | Обращение в поддержку. |
| `/legal/[slug]` | Оферта, политика, согласия и правила возврата. |
| `/admin` | Заказы, каталог, промокоды, контент, сотрудники, ролевые политики, почта и управление аккаунтами по назначенным правам. |
| `/tg-admin` | Административная Mini App внутри Telegram. |
| `/api/health` | Проверка доступности web и его связи с БД. |

Основной заказ: клиент выбирает товар, сервер рассчитывает стоимость и сохраняет заказ, платёжный сервис создаёт транзакцию, callback или сверка подтверждают результат, оператор выполняет заказ и отмечает завершение. Платёжный статус и исполнение заказа - разные этапы.

## 4. Данные и роли

PostgreSQL хранит пользователей, сессии, настройки 2FA, права сотрудников, игры и товары, заказы и платёжные попытки, сообщения, согласия, отзывы, медиа, настройки сайта и почты. Медиа, загруженные через админку, хранятся в таблице MediaAsset в виде байтов. Полный перечень моделей - в `app/prisma/schema.prisma`.

| Роль | Назначение |
| --- | --- |
| USER | Покупатель, собственные заказы и аккаунт. |
| SUPER_ADMIN | Владелец; управление сотрудниками и ключевыми настройками. |
| ADMIN | Менеджер в пределах административных проверок API. |
| CHAT_OPERATOR | Оператор; ограниченная работа с оплаченными заказами и сообщениями. |

`StaffAccess` отдельно задаёт `enabled`, `web`, `mini`, `bot`, `acceptedAt` и привязку `telegramId`. Одной роли недостаточно для всех каналов. `StaffRolePolicy` хранит уровни 0/1/2 для ADMIN и CHAT_OPERATOR по разделам; владелец редактирует политики, SUPER_ADMIN сохраняет полный доступ. API проверяет актуальную политику на каждом запросе и требует включённую 2FA для доступа сотрудника. Для чувствительных действий дополнительно проверяются пароль и фактор. Операции над сотрудниками ограничены правами действующей и назначаемой роли; владелец защищён отдельно. Mini App не содержит окна управления сотрудниками, но использует те же актуальные политики для доступных разделов.

Уведомления покупателя хранятся в `AccountNotification`; отмена заказа доступна до предусмотренного статусом этапа. Запрос удаления аккаунта даёт 72 часа: успешный вход в этот срок отменяет запрос, после срока вход блокируется, а окончательное обезличивание запускается уполномоченным сотрудником с повторным подтверждением. Платёжная история сохраняется в обезличенном виде согласно правилам хранения.

Пароли пользователей хешируются scrypt. Игровые реквизиты, чувствительные поля и пароль SMTP защищаются отдельными ключами. Ключи находятся в серверном `.env`, поэтому одного SQL-дампа для полного восстановления недостаточно.

## 5. Хранилища и сетевые границы

| Хранилище | Что сохранять при переносе |
| --- | --- |
| Docker volume `database` | Дамп PostgreSQL, совместимый с PostgreSQL 17. |
| Docker volume `telegram_state` | Состояние/курсоры доставки бота; переносить при остановленном worker. |
| Docker volumes `caddy_data`, `caddy_config` | Данные сертификатов и Caddy. На новом домене возможен новый выпуск сертификата. |
| `.env` | Ключи шифрования, секреты и окружение. Передавать закрытым каналом. |
| Исходники + lock-файлы | Восстановление сборки приложений. |

Публичные порты - 80 и 443; 3000 и 5432 остаются внутри сети Compose. Caddy закрывает `/api/internal`, `/tg-admin/api/internal` и Mini App health снаружи. Это не заменяет авторизацию в самом API.

Четыре независимых SMTP-профиля (`recovery`, `marketing`, `order`, `support`) и их зашифрованные пароли хранятся в PostgreSQL. Для восстановления нужен исходный `MAIL_ENCRYPTION_KEY`; API не возвращает пароли. Предпочтения писем сотрудников и покупателя проверяются вместе с действующими правами. Отчёты о резервировании настраиваются в профиле владельца. Токен Telegram и Platega Secret нельзя помещать в переменные `NEXT_PUBLIC_*`: эти переменные могут попасть в клиентскую сборку.

Приём новых платежей контролируют `TechnicalSettings.checkoutEnabled` и конфигурация Platega. Если поле БД задано, оно имеет приоритет над прежним `PLATEGA_ENABLED`; команды установки и отключения продаж синхронизируют оба уровня. Удалённый промокод помечается `archivedAt`, поэтому прошлые заказы и скидки остаются объяснимыми.

## 6. Где вносить изменения

| Задача | Основные точки изменения |
| --- | --- |
| Тексты и блоки витрины | Админка/контент БД, затем `app/components` и `app/lib/content-defaults.js`. |
| Каталог и цены | В первую очередь админка; расчёты в `app/lib/checkout-quote.js`, `pricing.js` и `sales-policy.js`. |
| Внешний вид | `app/app/*.css`, компоненты; Mini App проверяется отдельно. |
| Платежи | `app/lib/platega*`, `app/app/api/payments`, периодическая сверка. |
| Юридические страницы | `app/app/legal/[slug]`, `app/lib/config.js`, тексты документов и реквизиты `.env`. |
| Авторизация и 2FA | `session`, `account-security`, `staff-access`, `roles` и API auth/account. |
| Почта | `mailer.js`, `mail-profiles.js`, `mail-preferences.js`, четыре `MailSmtpProfile` и API проверки почты. |
| Права доступа | `admin-permissions.js`, `admin-permission-service.js`, `StaffRolePolicy`, проверки маршрутов web/Mini App. |
| Приём платежей | `payment-availability.js`, `checkout-policy.mjs`, `TechnicalSettings.checkoutEnabled` и `deploy/setup.py`. |
| Удаление аккаунта | `account-deletion.js`, `account-deletion-service.js`, `/api/admin/accounts/[id]/delete`. |
| Telegram | `telegram-bot/worker.mjs`, `core.mjs`, Mini App auth/internal API. |
| Изменение модели данных | Новая Prisma migration; обновить схему обоих приложений. |
| Домен / HTTPS / порты | `.env`, `compose.yaml`, `deploy/Caddyfile`; затем rebuild при смене домена. |

При доработке не заменяйте действующие миграции и не публикуйте дампы с реальными данными. Минимальный цикл изменения: отдельная ветка, тесты, сборка web и Mini App, проверка ролей и сценария, резервная копия перед обновлением, применённые миграции и проверка после запуска.

## 7. Что передаётся заказчику

Репозиторий с историей, переносимый установщик, шаблон окружения, Dockerfiles, миграции, тесты и [эксплуатационная документация](production/README.md). Готовые образы, приватные snapshots и серверная папка /root/backups не входят в публичные исходники. Защищённо и отдельно передаются доступы к VPS/DNS/GitHub, оригинальные ключи и рабочая база при переносе, кабинеты Platega/кассы/SMTP/Telegram. Логины, токены и данные покупателей не являются частью публичной технической документации.

Ответственные: владелец утверждает реквизиты, документы и порядок продаж; администратор отвечает за VPS, DNS, доступы, мониторинг и отдельные резервные копии; разработчик - за код, миграции, тестирование и исправления. Передача исходников сама по себе не означает, что реальные платежи, фискализация и все сценарии приёмки уже проверены.

Эта карта описывает файлы снимка, включая новые изменения RU/EN и административных проверок. Для подтверждения доступности функции нужны тег/идентичность образа, успешная сборка и проверка работающего интерфейса. VERSION снимка сам по себе этого не доказывает.

Переводы редактируемого контента хранятся рядом с исходными полями как contentI18n.en; системные фразы используют словари и SiteContent.data.translations. [Процедура RU/EN](TRANSLATIONS_RU_EN.md). Политика env удаляет семь устаревших SELLER-полей; юридические тексты проверяются отдельно в контенте и настройках, а не восстанавливаются простым возвратом этих полей в .env.
