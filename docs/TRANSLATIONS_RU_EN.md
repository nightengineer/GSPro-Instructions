# Перевод RU / EN на production-сервере

Сайт: https://gspro.store. Процедуры и механизм перевода сверены с локальным снимком исходников 27.09.2026; сборки, VPS и внешние интеграции в этой актуализации не проверялись. Команды выпуска ниже относятся к **действующему VPS** с `deploy/deploy-release.sh`, не к переносимому `install.sh` для нового сервера. Корень проекта — `/opt/gspro`. Русский текст является исходным: EN подставляет английский перевод, RU возвращает оригинал. Автоматического обратного перевода нет. После появления новых окон аккаунта, уведомлений, ролей и почтовых настроек проверяйте переводы web и Mini App отдельно.

## Редактируемый контент RU / EN

По исходникам снимка 27.09.2026 у редактируемого контента есть собственные поля RU/EN в админке (ContentLanguageEditor.js): игры, контакты, документы и слайды. Переключатель языка текста отделён от языка всего интерфейса. Изображения, цены, количество и включение элемента общие для обоих языков; сохранение записывает RU и EN. Подробная работа с окнами — в [ADMIN_GUIDE.md](ADMIN_GUIDE.md).

Явный перевод хранится у соответствующего объекта в contentI18n.en как {text, source}. После изменения RU редактор помечает старый EN как требующий проверки: перевод не обновляется автоматически. При отсутствии записи явного EN используется существующий словарь/шаблон; непереведённый текст остаётся исходным. Сохранённый явный EN с пустым текстом имеет приоритет и может скрыть поле в английской версии; очистка текста не удаляет запись перевода. Автоматический перевод здесь означает подстановку существующих словарных строк, без обращения к внешней службе.

Сверка исходников не подтверждает, что новые окна уже собраны в работающих образах. Сначала проверьте установленную версию; для обычного изменения контента в доступном редакторе выпуск кода не нужен. Для системных фраз и поведения локализации используйте процедуру ниже.

## Где лежит перевод

- `/opt/gspro/app/lib/english.json` — словарь сайта: точная русская фраза и её английский перевод.
- `/opt/gspro/app/lib/translation.js` — функция перевода и шаблоны строк с числами, датами и названиями.
- `/opt/gspro/app/components/Language.js` — переключатель языка, `T`, `useLanguage().t`, `Localized`.
- `/opt/gspro/telegram-admin/lib/english.json` — отдельный словарь Telegram Mini App; её функция перевода находится в `telegram-admin/components/Language.js`. Изменения словаря сайта сюда автоматически не копируются.

## Подготовить правку на VPS

Работайте в закрытом каталоге будущего релиза на сервере. Команды ниже создают уникальную папку и копируют в неё исходники; работающие контейнеры пока не меняются.

```bash
cd /opt/gspro
release_tag="ru-en-$(date -u +%Y%m%d-%H%M%S)"
release_dir="/root/gspro-releases/$release_tag"
install -d -m 700 "$release_dir"
cp -a app telegram-admin telegram-bot "$release_dir/"
nano "$release_dir/app/lib/english.json"
```

Выполняйте дальнейшие команды в той же SSH-сессии: переменные `release_dir` и `release_tag` должны сохраняться. Для Mini App редактируйте `$release_dir/telegram-admin/lib/english.json`.

## Как менять текст

Измените английское значение или добавьте пару внутрь существующего JSON-объекта:

```json
{
  "Каталог": "Catalog",
  "Поддержка": "Support"
}
```

Это пример формата, не замена всего словаря. Используйте UTF-8, двойные кавычки, запятые между парами, без комментариев и запятой после последней пары. Не дублируйте ключи.

Ключ должен точно совпадать с исходной русской фразой: регистр, пунктуация, внутренние пробелы и переносы строк имеют значение. Внешние пробелы при поиске убираются. При изменении русского текста в компоненте или админке добавьте перевод для новой формулировки. Изменение ключа словаря само по себе не меняет русский текст сайта.

Новые элементы должны использовать механизм локализации: `<T text="Поддержка"/>` либо `t('Поддержка')` из `useLanguage()`. Произвольный текст без такого вызова словарь не переводит. Для меняющихся чисел и названий проверьте шаблоны `translate`. Строки ответов API, уведомлений и писем локализуются отдельно от видимого React-компонента; не считайте словарь полным переводом всех каналов.

## Проверить и применить

Проверка синтаксиса JSON средствами Python на VPS:

```bash
python3 -m json.tool "$release_dir/app/lib/english.json" >/dev/null
python3 -m json.tool "$release_dir/telegram-admin/lib/english.json" >/dev/null
```

Обе команды должны завершиться без ошибок. Затем используйте штатный выпуск релиза текущего production:

```bash
bash /opt/gspro/deploy/deploy-release.sh "$release_dir" "$release_tag"
```

Скрипт берёт .deploy.lock, вызывает backup.py pre-release, переносит только app/telegram-admin/telegram-bot, задаёт APP_TAG/TG_ADMIN_TAG/TG_BOT_TAG, собирает три сервиса, применяет миграции и пересоздаёт сервисы. deploy/, Compose и README этой командой не обновляются; автоматического отката при ошибке нет. Подробнее — [регламент выпуска](production/README/17_Выпустить_новую_версию.md). Перед запуском проверьте доступность резервного копирования и состав релиза: в нём должна быть только согласованная правка. Обновление может вызвать краткий перерыв; параллельные изменения в админке не заменяют исходники релиза.

```bash
cd /opt/gspro
bash deploy/dc ps
bash deploy/dc logs --tail=50 web telegram-admin
curl -fsS https://gspro.store/api/health
```

Откройте сайт, обновите страницу и проверьте RU -> EN -> RU, включая изменённые места. Mini App проверяйте отдельно. При ошибке сборки не выполняйте дополнительные команды переключения контейнеров: сохраните лог и проверьте состояние сервисов. Простой restart не добавляет словарь в уже собранный образ.

`install.sh` описывает отдельный установочный пакет для нового сервера. На текущем production используется процедура выше; повторная установка для правки перевода не нужна. На новом VPS с переносимым комплектом измените исходники в отдельной ветке, проверьте оба JSON, выполните `sudo bash install.sh rebuild`, затем `sudo bash install.sh check`. Перед любой пересборкой подготовьте проверенную резервную копию и помните, что `rebuild` применяет миграции.

## Если перевод не изменился

Проверьте точное совпадение русского ключа, вызов локализации и успешную сборку нового релиза. В БД также поддерживается `SiteContent.data.translations`, запись `id: main`: непустой перевод из БД имеет приоритет над файлом. Для редактируемого контента есть отдельные поля EN рядом с RU; это не общий редактор всех системных строк словаря. Явный contentI18n.en выбранного объекта имеет приоритет перед словарным переводом. Старое поле SiteContent.data.translations продолжает участвовать в словарном механизме; его нельзя считать единственным местом перевода. При отсутствии записи функция пробует встроенные шаблоны, иначе оставляет исходный текст.
