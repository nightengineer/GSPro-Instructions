# Развёртывание GSPro

Для последнего полного S3-снимка используйте [интерактивный мастер на чистом Ubuntu](../server-setup/Инструкция_настройки_GSPro.md). Следующий текст сохраняет справочный порядок исходного комплекта и его дату.

> Разделы install.sh описывают переносимый установщик нового VPS. Серверные процедуры сверены с локальным снимком 27.09.2026; запуск установщика, сборки и внешние проверки здесь не выполнялись. Исходники на диске не доказывают наличие функций в работающих образах.

Действующий production: `https://gspro.store`, корень на VPS — `/opt/gspro`. [Эксплуатация текущего сервера](production/README.md). Установка через `install.sh` ниже относится к новому серверу; на текущем VPS используйте `deploy/dc` и `deploy/deploy-release.sh`.

Prod-1.1 | Переносимый комплект для нового VPS | 26 сентября 2026

## 1. Что будет установлено

Одна команда `sudo bash install.sh` подготавливает Docker Engine и Compose, собирает сайт, Mini App и бот, создаёт PostgreSQL, выполняет миграции, создаёт владельца и запускает сайт с HTTPS. Caddy получает и продлевает сертификат автоматически при доступном домене и портах. PostgreSQL наружу не публикуется.

Бот включается отдельной командой того же скрипта после ввода токена. Установка создаёт два служебных таймера: сверка платежей каждые 2 минуты и удаление завершённых игровых паролей каждый час. Резервное копирование в этот установщик не входит и на новом VPS должно быть настроено отдельно.

Поддерживаемая среда: отдельный чистый VPS, Ubuntu 24.04 LTS amd64, root или sudo. Минимум 2 vCPU, 4 ГБ RAM и 20 ГБ диска; для сборки предпочтительно 8 ГБ RAM. Установщик требует не менее 10 ГБ свободного диска. На занятом сервере с другими сайтами установку сначала согласуйте с администратором: Caddy использует 80/443.

## 2. Подготовка сервера и домена

1. Создайте VPS и войдите по SSH. Сохраните доступ в консоль провайдера.
2. В DNS создайте A-запись выбранного домена с IPv4 нового VPS. Если IPv6 не настроен, удалите AAAA для этого домена. Вводится домен без `https://`, порта и пути.
3. В firewall провайдера разрешите TCP 80, TCP 443 и ваш SSH-порт. UDP 443 нужен только для HTTP/3. Порт 5432 не открывайте. Если включён локальный firewall, проверьте его отдельно.
4. До первого запуска DNS должен указывать на VPS. Если переносите действующий домен, сначала используйте отдельный тестовый домен, а переключение выполните по разделу 7.

Установщик не меняет SSH, firewall и сетевые настройки хоста. Это сохраняет действующий доступ и не предполагает стандартный SSH-порт. Учтите: опубликованные Docker-порты могут обходить правила UFW; внешний firewall провайдера проверяется отдельно.

## 3. Установка нового сайта

Выполните на сервере:

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/nightengineer/GSPro.git /opt/gspro
cd /opt/gspro
sudo bash install.sh
```

Если репозиторий приватный, предоставьте VPS read-only deploy key. В GitHub: Settings / Deploy keys / Add deploy key, без Allow write access. Публичный ключ добавляется в GitHub, закрытый остаётся на VPS. Используйте SSH-URL `git@github.com:nightengineer/GSPro.git`. Не размещайте персональный токен в командной строке или URL.

Ответьте на три запроса: домен, email владельца, пароль владельца с повтором. Пароль: 12-128 символов, буквы и цифры; ввод скрыт. Ключи приложения и пароли БД скрипт создаёт сам. Реальные ключи хранятся в `/opt/gspro/.env` с правами 600. Пароль владельца сохраняется в БД только как хеш.

После сборки выполните:

```bash
sudo bash install.sh check
```

Проверка должна завершиться без ошибки: контейнеры запущены, web связан с БД, публичный HTTPS отвечает. Откройте сайт, войдите через `/auth/login`. Созданный владелец имеет роль SUPER_ADMIN; для входа в `/admin` сначала включите обязательную 2FA в профиле и сохраните коды восстановления.

Начальный каталог содержит демонстрационные позиции, выключенные на уровне игр. В админке задайте реальные товары, цены, лимиты и исполнителей. Не запускайте `db:seed` поверх рабочей базы: исторический скрипт может менять пользователя и каталог.

## 4. Ключевые файлы и переменные

Все пути ниже относительны `/opt/gspro`. Файл `.env` создаётся установщиком. Редактирование: `sudo nano /opt/gspro/.env`. Секреты не публикуются и не отправляются в поддержку. Одно значение занимает одну строку; установщик записывает значения в одинарных кавычках.

| Файл | Назначение / что менять |
| --- | --- |
| `.env` | Домен, продавец, платежи, Telegram, ключи. Основной серверный конфиг. |
| `.env.example` | Несекретный шаблон. Изменение шаблона не меняет работающий сайт. |
| `.env.runtime` | Создаётся автоматически; не редактировать. Административный пароль БД исключён. |
| `compose.yaml` | Контейнеры, тома, проверки здоровья, версии образов и портов. |
| `deploy/Caddyfile` | HTTPS и маршрутизация. Служебные API закрыты снаружи. |
| `deploy/Dockerfile` | Сборка web. `telegram-admin/Dockerfile` - Mini App; `telegram-bot/Dockerfile` - бот. |
| `install.sh`, `deploy/setup.py` | Единая точка запуска и реализация установки. |
| `app/prisma/schema.prisma`, `app/prisma/migrations` | Модель и история изменений БД. Не заменять миграции командой db push. |
| `/etc/systemd/system/gspro-*.timer` | Сверка платежей и очистка завершённых игровых паролей. |

| Переменные `.env` | Правило изменения |
| --- | --- |
| `DOMAIN` | Имя сайта. При смене домена нужны DNS, rebuild и новые URL у Platega/BotFather. |
| `APP_TAG` | Метка локальных образов: Prod-1.1. |
| `COMPOSE_PROJECT_NAME` | По умолчанию gspro. После установки не менять: имя определяет тома БД. |
| `POSTGRES_PASSWORD`, `RUNTIME_DB_PASSWORD` | Генерируются скриптом. Простая правка файла не меняет пароль внутри БД. |
| `APP_ENCRYPTION_KEY_BASE64`, `GAME_CREDENTIALS_KEY_BASE64`, `MAIL_ENCRYPTION_KEY` | Три независимых ключа шифрования. При переносе обязательно сохранять исходные значения. |
| `SESSION_SECRET`, `UID_HMAC_SECRET`, `IP_HASH_SECRET`, `CHECKOUT_TOKEN_SECRET` | Независимые секреты приложения. При переносе сохранять; смена требует отдельной процедуры. |
| `DEPLOY_MODE`, `PLATEGA_ENABLED` | Профиль выпуска и прежний платёжный флаг. Для новых платежей также действует `TechnicalSettings.checkoutEnabled` в БД; явное значение БД имеет приоритет над флагом. Используйте `enable-sales`/`disable-sales`, а не ручную правку одного поля. |
| `MIN_ORDER_RUB`, `MAX_ORDER_RUB`, `ORDER_EXPIRY_MINUTES`, `DEFAULT_MARKUP_PERCENT` | Общие параметры заказов; цены и доступность товаров также задаются в админке. |
| `TG_BOT_TOKEN`, `TG_CHAT_ID`, `TG_BOT_USERNAME`, `TG_BRIDGE_SECRET`, `TG_ENABLED` | Telegram. Настраивать командой telegram; токен и bridge secret не показывать пользователям. |
| `EMAIL_FROM`, `EMAIL_API_URL`, `EMAIL_API_TOKEN` | Альтернативный HTTP-сервис писем. Обычно используется SMTP через админку. |

После обычного изменения окружения выполните `sudo bash install.sh start`. После изменения кода или домена - `sudo bash install.sh rebuild`. Не используйте `docker compose config` для пересылки конфигурации: вывод может содержать секреты.

## 5. SMTP и Telegram

Почта: войдите владельцем в админку и откройте почтовые настройки. Для восстановления доступа, маркетинга, заказов и поддержки задаются **четыре независимых SMTP-профиля**: host, порт 465/587, логин, пароль и нужный адрес отправителя. Пароли хранятся зашифрованными в БД и не возвращаются через API; при переносе требуется исходный `MAIL_ENCRYPTION_KEY`. Нажмите проверку отправки для каждого используемого профиля и проверьте получение письма. Настройте SPF/DKIM/DMARC у почтового провайдера. Без работающей почты восстановление пароля и подтверждение регистрации не считаются принятыми. В профиле владельца отдельно настраивается получение писем с отчётами о резервировании.

Telegram: создайте бота через BotFather, добавьте его в нужную супергруппу. Включите темы (Topics), назначьте бота администратором с правом управления темами и отправки сообщений. На сервере:

```bash
cd /opt/gspro
sudo bash install.sh telegram
```

Скрипт запросит токен скрыто, ID супергруппы вида `-100...` и username бота без `@`. В BotFather настройте Main Mini App с URL `https://ВАШ-ДОМЕН/tg-admin`. Для старого домена замените URL. Доступ сотрудников назначьте и привяжите в разделе сотрудников веб-админки; список прав хранится в таблице StaffAccess.

Проверьте вход владельца и оператора в Telegram, разрешённые действия и отказ постороннему аккаунту. Mini App входит в основной запуск даже без токена, но Telegram-авторизация до настройки бота не работает. Режим `TG_SEND_TEST_ORDERS=false` оставляйте включённым для реальной группы, чтобы не пересылать тестовые заказы.

## 6. Как включить продажи

Укажите `SELLER_EMAIL` в `.env`, проверьте бренд, опубликованные юридические страницы, реквизиты и контакты в административных настройках. Поля `SELLER_TYPE`, `SELLER_NAME`, `SELLER_INN`, `SELLER_OGRN`, `SELLER_LEGAL_ADDRESS`, `SELLER_POSTAL_ADDRESS`, `SELLER_PHONE` выведены из окружения и удаляются синхронизацией; заполняйте актуальное содержимое через админку. Укажите `PD_OPERATOR_REGISTRY_NUMBER`, если применимо к вашей организации.

Получите рабочие настройки Platega и запишите в `.env`: `PLATEGA_MERCHANT_ID`, `PLATEGA_SECRET`. В кабинете платёжного сервиса задайте callback:

```text
https://ВАШ-ДОМЕН/api/payments/platega/callback
```

Четыре флага подтверждаются владельцем после фактической подготовки: `DATA_RESIDENCY_CONFIRMED=true`, `LEGAL_TEXTS_APPROVED=true`, `PAYMENT_FISCALIZATION_CONFIGURED=true`, `PROCESSOR_AGREEMENTS_CONFIRMED=true`. Эти флаги не подключают кассу и не создают договоры. В сборке не обнаружена самостоятельная интеграция фискализации; рабочую схему чеков нужно обеспечить и проверить отдельно.

```bash
sudo bash install.sh enable-sales
sudo bash install.sh check
```

Команда сначала проверяет конфигурацию в отдельном контейнере. При отказе preflight файл и текущий режим не меняются. При успехе устанавливает `PLATEGA_ENABLED=true`, `DEPLOY_MODE=production`, пересоздаёт сервисы и **только после успешного запуска** устанавливает `TechnicalSettings.checkoutEnabled=true`. Если запуск прервался, проверьте состояние БД и контейнеров до повторения. Владелец может позже выключать и включать приём оплаты в админке; переключатель БД имеет приоритет над старым флагом окружения.

До публичного открытия: провести согласованную небольшую оплату, убедиться в правильной сумме, callback, статусе заказа, чеке, письме и исполнении. Проверить повторный callback, отмену и возврат. В текущем коде статус REFUNDED не инициирует возврат в платёжной системе: деньги возвращаются отдельно через согласованный процесс провайдера, статус меняется после подтверждения факта.

Для отключения реальной оплаты:

```bash
sudo bash install.sh disable-sales
```

Команда сначала устанавливает `TechnicalSettings.checkoutEnabled=false`, затем меняет окружение. Это отключает создание новых реальных платежей, но не является полной страницей технических работ. Витрина остаётся доступной. Ранее выданные ссылки, открытые заказы и незавершённые платежи требуют отдельной сверки с провайдером. Для действующего VPS используйте сверенный `deploy/disable-payments.sh` по [инструкции окружения](CHECK_ENV_RU.md); он сначала закрывает checkoutEnabled в БД, а затем пересоздаёт web и Mini App. Callback и сверка существующих транзакций при сохранённых ключах продолжают действовать.

## 7. Перенос существующей базы на другой VPS

Перенос данных выполняется отдельно от Git. На старом сервере остановите приём новых заказов и изменения данных на время финального снимка. Не считайте `disable-sales` полной заморозкой: доступ к админке и другим операциям также нужно остановить. Экспортируйте PostgreSQL в custom format `pg_dump -Fc`, сохраните оригинальные `.env` и `.env.telegram` защищённым способом.

На новом VPS создайте `/root/gspro-transfer` с правами 700. Передайте в неё `database.dump` (`pg_dump -Fc`) и **оригинальный** `.env`, при наличии `.env.telegram` и согласованный `state.sqlite`. Права файлов — 600. Используйте защищённую передачу, не GitHub, email или чат. Если закрытый архив на сервере содержит каталоги `transfer/` и `live-site/` внутри архива, используйте вложенный путь после распаковки. После проверки контрольных сумм и распаковки в `/root/gspro-transfer` передавайте `--restore-dir /root/gspro-transfer/transfer`; либо скопируйте только содержимое `transfer/` прямо в `/root/gspro-transfer` для команды ниже. Публичный репозиторий этих данных не содержит. Загруженные изображения, почтовые профили и ролевые политики находятся в PostgreSQL; статические изображения входят в репозиторий.

```bash
sudo chmod 700 /root/gspro-transfer /root/gspro-transfer/transfer
sudo chmod 600 /root/gspro-transfer/transfer/database.dump
sudo chmod 600 /root/gspro-transfer/transfer/.env
cd /opt/gspro
sudo bash install.sh install --restore-dir /root/gspro-transfer/transfer
```

Установщик не перезаписывает непустую базу. Сохраняет исходные ключи, импортирует данные без старых владельцев PostgreSQL, применяет миграции, выдаёт приложению ограниченные права. Существующие логины, роли, четыре SMTP-профиля, подписки и каталог сохраняются; новый владелец не создаётся. `checkoutEnabled` принудительно устанавливается в `false` **после миграций и до запуска сервисов**, даже если в дампе было `true`. Бот на новой копии первоначально выключен.

Состояние доставки бота хранится отдельно в томе `telegram_state` (SQLite). Подготовьте согласованный standalone-снимок через SQLite backup API. На старом VPS, пока контейнер бота существует, можно определить каталог тома и сделать согласованную копию даже при работе WAL:

```bash
cd /opt/gspro
bot_container=$(bash deploy/dc ps -q telegram-bot)
bot_state_dir=$(docker inspect --format '{{range .Mounts}}{{if eq .Destination "/data"}}{{.Source}}{{end}}{{end}}' "$bot_container")
install -d -m 700 /root/gspro-transfer
GSPRO_BOT_STATE_DIR="$bot_state_dir" python3 - <<'PY'
import os, sqlite3
from pathlib import Path
source = Path(os.environ['GSPRO_BOT_STATE_DIR']) / 'state.sqlite'
target = Path('/root/gspro-transfer/state.sqlite')
with sqlite3.connect(f'file:{source}?mode=ro', uri=True) as src, sqlite3.connect(target) as dst:
    src.backup(dst)
    assert dst.execute('PRAGMA integrity_check').fetchone()[0] == 'ok'
target.chmod(0o600)
PY
```

Для финального переключения остановите старый worker и повторите снимок из того же каталога тома, затем передайте `state.sqlite` вместе с дампом БД. Не копируйте только основной файл работающей WAL-базы. Установщик проверяет целостность, таблицу `state` и импортирует файл в пустой том. Без переноса состояния возможна повторная обработка старых сообщений/заказов. Не запускайте один токен бота одновременно на двух VPS.

Если сначала использовали тестовый домен: измените DOMAIN на основной, переключите DNS, выполните `rebuild`, обновите Platega callback и BotFather. Проверьте владельца, каталог, медиа, SMTP и здоровье БД. Только затем включайте продажи и нового бота. Старый сервер сохраняйте до завершения приёмки и проверки отдельной резервной копии.

## 8. Проверка и диагностика

```bash
cd /opt/gspro
sudo bash install.sh check
sudo bash deploy/dc ps
sudo bash deploy/dc logs --tail=100 web
sudo bash deploy/dc logs --tail=100 telegram-admin
sudo bash deploy/dc logs --tail=100 caddy
sudo systemctl list-timers 'gspro-*'
```

| Симптом | Действие |
| --- | --- |
| GitHub 403 / Repository not found | Проверить права аккаунта или deploy key. Не публиковать токен. |
| Сборка убита / exit 137 | Проверить память и диск; увеличить RAM. Повторить install с теми же параметрами. |
| Ошибка сертификата | Проверить A/AAAA, доступность 80/443 извне и логи Caddy. Не удалять caddy_data. |
| Preflight stopped | Исправить перечисленные переменные; не обходить проверку включением другого режима. |
| Invalid encryption key | Вернуть исходные ключи из защищённого конфига. Новый ключ не расшифрует старые данные. |
| Existing project volumes | Выбран не чистый проект. Скрипт остановился для защиты данных; не удалять тома вслепую. |
| Earlier restore failed | Импорт не продолжается автоматически. Проверить ошибку; использовать новую пустую тестовую установку или восстановление с администратором. |

При прерывании обычной установки повторите исходную команду: `.env` и ключи сохранятся. Завершённая установка повторный install отклоняет; используйте start/check/rebuild. Если пользователь уже создан, а маркер owner не записался, сначала проверьте вход; установщик намеренно не меняет существующий пароль. Не удаляйте `.state` без выяснения причины.

Служебные команды для сверки одного спорного платежа выполняет администратор после проверки UUID в кабинете: `sudo bash deploy/dc exec -T web node scripts/platega-reconcile.mjs UUID`. Не повторяйте создание оплаты для зависшего платежа без проверки провайдера.

## 9. Обновление и приёмка

Перед обновлением сделайте отдельную проверенную резервную копию БД и конфигурации. В этом пакете бэкапы не устанавливаются. Не обновляйте рабочий код через случайный архив поверх каталога.

```bash
cd /opt/gspro
sudo git pull --ff-only
sudo bash install.sh rebuild
sudo bash install.sh check
```

Обновление может дать короткий перерыв. Откат кода не откатывает миграции БД; для несовместимой миграции нужен заранее проверенный план восстановления. Базовые Docker-образы используют обновляемые теги, поэтому новая сборка в будущем может получить более свежие компоненты.

Приёмка: HTTPS; вход и 2FA владельца; каталог и медиа; проверка SMTP; Mini App и роли; работа бота; реальная оплата, чек и возврат; внешнее наблюдение за доступностью; отдельное резервное копирование и тест восстановления. Для каждого пункта нужен результат, а не только выставленная галочка.

Проверки этого пакета и их границы опубликованы в `docs/VERIFICATION.md`. Установка контейнеров проверяется отдельно от создания нового VPS, публичного DNS и реальных внешних сервисов.

## 10. Установка веб-приложения на Android и iPhone

Ссылка для пользователей текущего сайта: [Открыть GSPro для установки - https://gspro.store/](https://gspro.store/).

1. Откройте ссылку в Chrome на Android. Если она открылась внутри Telegram или другого приложения, выберите открытие во внешнем браузере.
2. Примите предложение установки либо откройте меню ⋮: «Установить приложение» или «Добавить на главный экран» → «Установить». Формулировка зависит от браузера и версии Android.
3. Подтвердите установку. Запускайте GSPro Store через появившуюся иконку. Если приложение уже установлено, браузер может предложить открыть его.

На iPhone используется та же веб-версия. Откройте ссылку в Safari, нажмите «Поделиться», выберите «На экран “Домой”». Если доступен переключатель «Открывать как веб-приложение», включите его. Нажмите «Добавить» и запускайте сайт через новую иконку. Если пункта добавления нет, проверьте список действий в меню «Поделиться». [Официальная инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iphea86e5236/ios).

Ссылка ведёт на сайт, а не на APK. Она не гарантирует автоматическое появление диалога: решение принимает браузер, установку подтверждает пользователь. Отдельная публикация в Google Play или App Store не выполнялась. Полный сценарий GSPro на реальном iPhone ещё требует приёмки.

Установленная версия использует тот же интерфейс и сервер: отдельная база, сборка Android и синхронизация заказов не нужны. Для покупок и работы аккаунта требуется интернет. Офлайн-режим и push-уведомления не реализованы. Обновления веб-интерфейса доступны через сайт; при устаревшем экране перезапустите приложение и проверьте соединение.

Настройки установки: `app/app/manifest.js`, публичный адрес `/manifest.webmanifest`. Изменяемые поля: name/short_name (название), icons (иконка), start_url (стартовая страница), display (standalone), theme_color/background_color (цвета). Изменения требуют rebuild. При переносе на новый домен замените ссылку установки в документации на его HTTPS-адрес. Ранее установленная копия остаётся привязанной к прежнему сайту; для нового домена установите приложение заново.

Приёмка на телефоне: установить через браузер, проверить иконку, запуск, вход, каталог и открытие оплаты. Сам факт установки не подтверждает работу всех платёжных переходов внутри установленного окна.

Источники: https://docs.docker.com/engine/install/ubuntu/ ; https://caddyserver.com/docs/automatic-https ; https://support.google.com/chrome/answer/9658361 .
