# Бот и очередь Telegram

Карта исходников: 28.09.2026.

Один worker связывает события сайта с карточками и темами Telegram. Локальная SQLite хранит курсоры, связи тем и карточек.

## Поток

PostgreSQL `TelegramEvent` → внутренний API Mini App → worker → Telegram API → подтверждение доставки/повтор.

Одна тема соответствует покупателю; заказы внутри неё имеют отдельные карточки. Текущее `topicName` использует переданный `customerEmail`, иначе короткий идентификатор. Это передача контактного значения в Telegram; доступ к группе нужно учитывать отдельно от прав API. В этой документации реальные email не приводятся.

Кнопки «Ответить» и «Изменить статус» ведут в Mini App. Прямые административные `reply/status` через bridge отвергаются. Само членство в группе не даёт права изменять заказы.

Запускается одна реплика polling-бота. Volume `telegram_state` нельзя считать временным кэшем. Согласованный снимок SQLite делают при остановленном worker либо через SQLite Backup API; копировать только основной файл работающей WAL-базы нельзя. Telegram может повторить доставку при неопределённом сетевом результате.

Исходники: `telegram-bot/worker.mjs`, `core.mjs`, `health.mjs`, `telegram-admin/app/api/internal/telegram/route.js`.
