# Сборка, выпуск и откат

Карта исходников: 26.09.2026.

Исходники → проверки → три Docker-образа → резервная копия → миграции → запуск → проверка сценариев. Git push сам по себе не обновляет VPS.

## Различайте два процесса

- **Новый VPS:** переносимый `install.sh`, `deploy/setup.py`, Compose, миграции и первичная настройка. Для переноса нужны закрыто переданные дамп и исходные ключи.
- **Действующий VPS:** проверенные серверные процедуры через `deploy/dc` и инструкцию выпуска релиза. Наличие пути в инструкции не означает, что серверный скрипт уже установлен на новом хосте.

`migrate` - отдельный одноразовый сервис. Runtime-подключения web/mini и административная роль миграций различаются. Исходные Prisma migrations не заменяют задним числом; добавляют новую миграцию.

Перед очисткой сохраняют текущие immutable image ID, последний пригодный rollback и свежую проверенную копию БД. Теги могут перемещаться и не заменяют точную фиксацию образа. Откат кода не откатывает схему БД автоматически.

Синтетические интеграционные тесты используют отдельные контейнеры, внутреннюю сеть и отдельную БД; настоящие SMTP/платежи не участвуют. Прохождение тестов не равно приёмке внешних сервисов.

Исходники: `compose.yaml`, `deploy/Dockerfile`, `telegram-admin/Dockerfile`, `telegram-bot/Dockerfile`, `install.sh`, `.github/workflows`, `docs/DEPLOY.md`.
