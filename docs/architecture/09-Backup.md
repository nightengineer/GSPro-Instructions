# Полная резервная копия

Карта исходников: 26.09.2026.

Закрытая резервная копия дополняет GitHub: сохраняет базу, исходные ключи, образы, состояние бота и сведения для восстановления сервера.

## Порядок в backup-full.py

1. Остановить писателей и прокси на время согласованного снимка; PostgreSQL остаётся для pg_dump.
2. Выгрузить database.dump, проверить список восстановления; сохранить настройки и состояние бота/прокси.
3. Сохранить исходники и сведения о контейнерах, проверить соответствие тегов image ID; вернуть сервисы, затем экспортировать проверенные образы.
4. Собрать архив, зашифровать CMS/AES-256-GCM по сертификату получателя.
5. Выгрузить в S3 и проверить обратным чтением точные байты/SHA256.
6. Применить настроенное хранение после подтверждения копии; записать результат и отправить служебное уведомление.

Полный архив может содержать `.env`, дампы, закрытые конфигурации и системный снимок. Его нельзя публиковать в GitHub или прикладывать к открытому отчёту. Ключ восстановления хранится отдельно, в согласованном защищённом месте.

Установщик нового сервера сам по себе не подтверждает наличие расписания S3-backup. Настройка backup относится к конкретному установленному серверу. Успешный последний снимок подтверждают receipt и проверка восстановления, а не наличие скрипта.

Исходники: `deploy/backup-full.py`, `backup-release-variants.py`, `backup-notify.mjs`, эксплуатационные инструкции `docs/production`.
