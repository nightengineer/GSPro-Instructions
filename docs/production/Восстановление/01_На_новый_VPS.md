# Восстановление на новом VPS

Редакция: **28.09.2026**. Основной путь — [интерактивный мастер на чистом Ubuntu](../../../server-setup/Инструкция_настройки_GSPro.md). [Карта способов и ручной путь из S3](../../recovery/README.md) полезны как запасной порядок.

1. Подготовьте новый пустой Ubuntu 24.04 x86-64, консоль провайдера и публичный SSH-ключ владельца. Нужен запас диска для снимка, распаковки и одного комплекта из пяти образов. Не запускайте installer поверх существующего сайта.
2. Получите полный независимый recovery-kit из выбранного S3. Проверьте внешний SHA256 и внутренний `MANIFEST.sha256`. Используйте инструменты этого комплекта; папка `system/deployment` прежнего снимка может содержать более старый установщик.
3. Скачайте нужный полный `.cms` и `.sha256`, расшифруйте защищённым PEM с отдельным паролем и проверьте внутренний `SHA256SUMS`. Для старого снимка может требоваться прежняя версия приватного ключа.
4. Подготовьте мастер: он сохраняет исходные ключи и теги, берёт версии Docker из `host-packages.txt`, создаёт настроенную копию installer с `START_PUBLIC_SERVICES=false`. Домен текущих сохранённых образов — `gspro.store`; другой домен требует отдельной сборки и проверки.
5. По инструкции мастера отдельно выполните installer, затем `--apply`. Installer загружает сохранённые образы, восстанавливает пустую БД/SQLite и выборочные конфигурации. Публичные службы остаются остановлены. Не запускайте `docker pull` вместо восстановления сохранённых образов.
6. Проверьте ID образов, исходные ключи, оба S3, права сотрудников, 2FA и изменения после даты снимка. Не копируйте всё `/etc`, старые SSH host keys, сетевые настройки или SSH-каталоги поверх нового сервера.
7. При полной потере VPS используйте последний пригодный доступный снимок и убедитесь, что прежний экземпляр не возобновится параллельно. При плановом переносе сначала остановите запись на старом экземпляре, получите финальный снимок и сохраняйте обработчики остановленными до переключения. Если новый экземпляр уже восстановлен для репетиции, не импортируйте финальный дамп поверх непустой БД: подготовьте отдельное пустое восстановление.
8. По отдельному решению переключите DNS A/AAAA и запустите единственный комплект сервисов. Проверьте HTTPS, web, Mini App, единственного бота, SMTP и платёжные callback. Сверьте галочку «Приём платежей на сайте» до открытия покупателям.
9. Создайте новую ручную дневную копию. Только после успешной проверки её загрузки в обоих S3 включайте расписание и проверяйте уведомление владельцу.

После частичного сбоя installer не удаляйте приложение или БД ради повторного запуска: определите незавершённый шаг и продолжите по проверенному плану. Полная репетиция на новом VPS и внешняя приёмка этим документом не подтверждаются.
