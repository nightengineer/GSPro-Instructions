# Восстановление на новом VPS

Для последнего полного S3-снимка используйте [интерактивный мастер на чистом Ubuntu](../../../server-setup/Инструкция_настройки_GSPro.md). Следующий текст сохраняет справочный порядок исходного комплекта и его дату.

1. Подготовить пустой Ubuntu 24.04 x86-64, диск с запасом под распаковку и два набора образов, доступ к консоли и SSH. Не запускать установщик поверх существующего сайта.
2. Скачать полный актуальный .cms и .sha256 из S3, защищённый приватный PEM — из отдельного префикса. Сверить SHA256.
3. Установить Python cryptography и запустить `python3 decrypt-cms-stream.py snapshot.cms private.encrypted.pem snapshot.tar.gz`. Пароль вводится скрыто. Оригинальный незашифрованный PEM также поддерживается без пароля.
4. Распаковать snapshot в `/root/restore-prod11` с правами 700; внутри выполнить `sha256sum -c SHA256SUMS`. Затем взять этот комплект из `system/deployment`.
5. В `deploy-new-vps.sh` заполнить NEW_SERVER_IP, DOMAIN, SSH_PUBLIC_KEY_FILE, SNAPSHOT_DIR. Оставить START_PUBLIC_SERVICES=false. Проверить закреплённые версии Docker; если репозиторий больше их не предоставляет, остановиться и выбрать проверенные версии, не убирать ограничения вслепую.
6. Запустить установщик. Он загружает сохранённые Docker-образы, восстанавливает пустую БД и SQLite, устанавливает конфигурации из явного списка. Новые host keys, сеть и диски нового VPS не заменяются старым /etc.
7. Восстановить доступ к S3 отдельными новыми credentials с правами 600. Сверить ключи приложения, права сотрудников, использованные 2FA-коды, последние оплаты/возвраты после времени snapshot. Провести закрытые проверки сайта и Mini App.
8. Остановить старый бот и обработчики, создать финальный snapshot при переносе работающего сервера. Восстановить финальное состояние на закрытом новом экземпляре; переключить DNS и запустить единственный комплект сервисов.
9. Проверить HTTPS, web, Mini App, bot, SMTP, callback и ручную дневную копию с обратной проверкой S3. Только после успешной копии включить backup timers. Проверить уведомление суперпользователям.

Старую всю папку /etc и ssh-client.tar.gz не распаковывать поверх нового сервера автоматически. Извлекать нужное выборочно. Сертификаты можно получить заново через Caddy; proxy-volumes сохранены как дополнительная возможность восстановления.
