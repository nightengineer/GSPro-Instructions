# Комплект восстановления GSPro

Редакция: **28.09.2026**. Для нового пустого VPS сначала используйте [мастер](../../../server-setup/Инструкция_настройки_GSPro.md). [Карта способов](../../recovery/README.md) описывает независимый комплект S3 и запасной ручной порядок.

Полный snapshot включает `database.dump`, `application.tar.gz`, `telegram-state.tar.gz`, `images.tar.gz`, `system/`, `images.json`, `containers.json`, `host-packages.txt`, `SHA256SUMS` и `BACKUP-FORMAT.json`. Дополнительные файлы зависят от формата выбранного снимка; сверяйте его манифест. Текущий комплект приложения один, с пятью образами: web, Mini App, бот, PostgreSQL и Caddy.

Независимый recovery-kit хранится отдельно от зашифрованного snapshot в каждом S3: он нужен даже при полной потере старого VPS. Публичные исходники инструментов не заменяют полный приватный kit. Защищённый PEM требует отдельного пароля владельца; S3 credentials не заменяют пароль расшифровки. Для прежних снимков после смены самого приватного ключа сохраните соответствующие старые версии из `gspro/recovery-keys/`.

Проверяйте внешний SHA256, аутентификацию CMS и внутренний `SHA256SUMS` перед восстановлением. Не используйте частичный вывод. Полный snapshot, env, дампы и приватные ключи не публикуются. Проверка наличия файлов не заменяет репетицию восстановления на отдельном пустом VPS.
