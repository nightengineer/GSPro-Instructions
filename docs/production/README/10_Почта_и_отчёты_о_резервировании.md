# Почта и отчёты о резервировании

Версия комплекта: **Prod-1.1**. Основная папка сайта: `/opt/gspro`. Команды выполняются на VPS по SSH от root, если не указано другое.

Войдите владельцем, откройте **свой профиль → «Отчёты о резервном копировании»** и измените персональную галочку. Раздел виден только SUPER_ADMIN. В административных почтовых настройках отдельно задаётся SMTP-профиль `support`, через который отправляются отчёты; остальные независимые профили обслуживают восстановление, маркетинг и заказы.

У каждого суперадмина своя подписка, общая для сайта и Mini App. Галочка меняет только подписку вошедшего пользователя. Пока изменения не сохранены, список показывает сохранённое состояние.

Получатели: подписанные SUPER_ADMIN, без удаления или запроса удаления, с разрешённым и принятым доступом StaffAccess. Обычные ADMIN и операторы отчёты не получают. Если никто не подписан, показано «Никто не подписан».

Включённая галочка разрешает SUCCESS/WARNING/FAILED для своей учётной записи. Выключенная отключает эти письма только для неё, но не создание копий и не подписки остальных. При обработке очереди получатели выбираются по текущим подпискам; при отсутствии получателей событие помечается skipped и не рассылается позднее.

Подписка хранится в User.backupReportEnabled. Миграция 20260924010000_individual_backup_reports переносит прежний общий флаг существующим суперадминам; новые аккаунты по умолчанию не подписаны. Старое поле TechnicalSettings.backupReportEnabled сохранено для совместимости, новая рассылка его не использует. Скрипт отправки на VPS: /root/backups/scripts/notify.mjs; актуальная поставочная копия: deploy/backup-notify.mjs.

Очередь: `/root/backups/notifications`, отправленные события: `sent`, отключённые: `skipped`. Повторы доставки каждые 5 минут. Скрипт использует актуальный `MailSmtpProfile` операции `support` и лишь при его отсутствии старую общую SMTP-конфигурацию. Принятие письма SMTP-сервером не доказывает попадание во «Входящие».
