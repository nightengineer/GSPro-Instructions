# Перенести на другой VPS

Редакция: **28.09.2026**. Для восстановления используйте [интерактивный мастер](../../../server-setup/Инструкция_настройки_GSPro.md) и [порядок нового VPS](../Восстановление/01_На_новый_VPS.md). Полный приватный snapshot и независимый recovery-kit получите из своего S3.

Сначала подготовьте и проверьте закрытый новый экземпляр на пустом Ubuntu 24.04 x86-64. Не запускайте второго бота и не направляйте покупателей на непроверенную БД.

Для окончательного планового переноса остановите запись и обработчики на старом VPS, получите финальный согласованный snapshot и сохраняйте старый экземпляр остановленным. Восстановите финальное состояние в пустое целевое окружение; репетиционная непустая БД не подходит для повторного полного импорта. Переключите DNS и единственный рабочий экземпляр после проверок.

Проверьте состояние приёма новых платежей в админке, операции после даты снимка, HTTPS, SMTP, callback и единственного Telegram-бота. Подтвердите новую копию в обоих S3, затем включите резервное расписание.
