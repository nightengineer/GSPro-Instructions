# Подключить и проверить S3

Редакция: **28.09.2026**. Основная папка сайта: `/opt/gspro`. Команды выполняются на VPS по SSH от root.

Резервирование использует два независимых закрытых хранилища:

| Провайдер | Endpoint | Регион подписи | Конфигурация / credentials |
| --- | --- | --- | --- |
| Timeweb | `https://s3.twcstorage.ru` | `ru-1` | `/root/backups/s3-config.json` / `/root/backups/s3-credentials.json` |
| REG.RU | `https://s3.regru.cloud` | `us-east-1` | `/root/backups/regru-s3-config.json` / `/root/backups/regru-s3-credentials.json` |

Бакеты и префиксы сверяйте в конфигурациях владельца. Credentials доступны только root, права 600. Доступам для регулярного резервирования нужны List/Get/Put/Delete в согласованных префиксах. Секреты не вводите в командную строку и не публикуйте конфигурации целиком.

```bash
python3 /root/backups/scripts/s3_store.py check
cat /root/backups/multi-s3-last-success.json
```

Команда проверки должна подтвердить оба хранилища. Квитанция должна относиться к выбранному свежему снимку и содержать успешные результаты обоих S3. Наличие старой квитанции не подтверждает текущую загрузку.

Загрузка проверяет точные байты/SHA256 обратным чтением; ETag multipart-загрузки не равен SHA256 всего архива. Аутентификация CMS и проверка восстановления БД выполняются отдельно. При сбое одного S3 ожидающие загрузки копии сохраняются на VPS: контролируйте диск и повтор загрузки.

Полнота исторических префиксов может отличаться: новый зеркальный S3 не гарантирует наличия всех прежних снимков. Для восстановления выберите доступный снимок нужной даты по [карте способов](../../recovery/README.md).
