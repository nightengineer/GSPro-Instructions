# Реестр доступов для передачи — без секретов

Редакция: **28.09.2026**.

Вписать владельца и проверить доступ совместно с заказчиком. Пароли/токены/ключи в этот файл не добавлять.

| Система | Что передать и проверить | Ответственный / статус |
|---|---|---|
| Домен и DNS | Кабинет регистратора, DNS-зона, продление, 2FA | Заполнить |
| VPS | Кабинет провайдера, консоль, root/SSH-ключ, биллинг | Заполнить |
| Timeweb S3 | Кабинет, bucket, endpoint/region, ограниченные credentials, биллинг | Заполнить |
| REG.RU S3 | Отдельный кабинет, bucket, endpoint/region, ограниченные credentials, биллинг | Заполнить |
| Резервные копии | Доступ к архиву, приватный ключ, пароль защищённого ключа, проверка восстановления | Заполнить |
| Приложение | SUPER_ADMIN заказчика, принятие доступа, 2FA и резервные коды | Заполнить |
| Telegram | Владение ботом/BotFather, группа, права, Mini App URL, токен | Заполнить |
| SMTP и доменная почта | Кабинет, почтовые ящики, SMTP, DNS-записи, восстановление | Заполнить |
| Платежи и чеки | Мерчант, доступы ответственных, callback, кассовая схема | Заполнить |
| Репозиторий | Организация/репозиторий, release tag, CI, журнал изменений | Заполнить |
| Мониторинг | Кто получает события, внешний контроль при недоступности VPS | Заполнить |

После приёмки отозвать ненужные доступы разработчиков по согласованному списку. Пароли и API credentials можно ротировать планово; ключи шифрования уже существующих данных менять только вместе с отдельной миграцией и проверкой восстановления.
