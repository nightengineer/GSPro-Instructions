# Выпустить новую версию установленного GSPro

Корень VPS: /opt/gspro. Процедура сверена с deploy/deploy-release.sh в локальном снимке 27.09.2026; сам выпуск в этой сверке не выполнялся.

1. Подготовьте согласованные app/, telegram-admin/ и telegram-bot/ в отдельном каталоге релиза. Скрипт требует app/; отсутствующие два других компонента он оставляет прежними. Для согласованного выпуска всех трёх включите их явно.
2. Проверьте код, обе сборки, тесты и миграции на отдельной базе с отключёнными внешними отправками. Выберите новый неизменяемый тег; проверьте готовность восстановления и доступность /root/backups/scripts/backup.py.
3. Запустите штатную команду от root:

```bash
bash /opt/gspro/deploy/deploy-release.sh /root/gspro-releases/КАТАЛОГ НОВЫЙ_ТЕГ
```

Скрипт берёт .deploy.lock, вызывает backup.py pre-release и прекращает работу при его ошибке. Проверку загрузки/восстановимости архива сверяйте с протоколом резервирования: один факт вызова backup.py её не доказывает. Скрипт копирует только прикладные компоненты через rsync --delete, исключая .env*, node_modules и .next. deploy/, Compose и README этой командой не обновляются: их согласованное изменение требует отдельной процедуры.

Затем исправляются права, меняются APP_TAG в .env и TG_BOT_TAG/TG_ADMIN_TAG в .env.telegram, собираются три сервиса, запускается migrate, выполняется up -d --no-build --wait и verify-miniapp.sh. VERSION записывается только после этих шагов. Автоматического отката при ошибке нет; исходники и часть env могли уже измениться. RELEASE_VERSION этим скриптом не синхронизируется с произвольным тегом.

Не заменяйте ключи шифрования вместе с обычным релизом. Откат образа не откатывает миграции; совместимость старого кода с новой БД проверяется заранее. Не выпускайте релиз одновременно с восстановлением или несогласованными изменениями исходников.

После выпуска выполните [общую проверку](33_start_and_check.md) с --check-only и проверку изменённых пользовательских сценариев, прав, Telegram и SMTP. verify-miniapp.sh проверяет HTTP-коды публичных/закрытых маршрутов и health четырёх сервисов, но не реальную оплату, доставку письма или сообщения. Проверьте новую дневную копию по регламенту, отдельно зафиксируйте тег, контрольные суммы и ограничения.
