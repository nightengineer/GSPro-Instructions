# Скачать и проверить резервную копию

Редакция: **28.09.2026**. Восстановление выполняется на предназначенном новом VPS, а не на локальном ПК.

1. Получите полный независимый recovery-kit из доступного закрытого S3 и проверьте его SHA256 и `MANIFEST.sha256` по [мастеру](../../../server-setup/Инструкция_настройки_GSPro.md) либо [ручному порядку](../../recovery/README.md).
2. Запустите downloader комплекта: выберите провайдера, нужный `daily`, `monthly` или `pre-release` снимок. Проверьте дату: последний снимок может уже содержать повреждение.
3. Downloader скачает `.cms`, соответствующую SHA256 и текущий защищённый приватный PEM. Для снимка с прежним приватным ключом получите соответствующую версию из `gspro/recovery-keys/`.
4. Расшифруйте через `tools/decrypt-cms-stream.py` комплекта в интерактивном терминале. Пароль берите из отдельного защищённого хранилища владельца. При ошибке GCM или SHA256 остановитесь.
5. Распакуйте в новый закрытый каталог, выполните `sha256sum -c SHA256SUMS`, проверьте `BACKUP-FORMAT.json`, `images.json` и `host-packages.txt`.

Снимок содержит конфиденциальные env, БД и состояние приложения. Не публикуйте его или вывод файлов с секретами. Для доказательства восстановления нужны отдельная проверка PostgreSQL, SQLite, образов, расшифровки полей и входов. Контрольная сумма сама по себе не подтверждает логическую полноту БД или доверенность источника.
