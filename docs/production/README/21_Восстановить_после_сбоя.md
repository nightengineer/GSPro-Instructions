# Восстановить после сбоя

Редакция: **28.09.2026**.

Установленный GSPro. Основная папка сайта: `/opt/gspro`. Команды выполняются на VPS по SSH от root, если не указано другое.

Если данные целы: сначала диагностировать сервис/диск/сеть. Для запуска только существующих контейнеров используйте `sudo bash /opt/gspro/deploy/start-and-check.sh` по [инструкции](33_start_and_check.md); старый дамп поверх актуальных данных не импортируйте. Если копирование прервалось и есть restart-needed.json, сначала разберите состояние штатного recover.py: скрипт запуска не заменяет восстановление после прерванного snapshot.

Если данные утрачены: следовать `../Восстановление/02_После_падения_текущего_VPS.md`. Сохранить повреждённый экземпляр отдельно, проверить выбранный snapshot, восстановить в пустую БД и отдельное состояние бота, сверить доступы и последние платежи.

Нельзя автоматически удалять непустую БД ради восстановления. Скрипт restore.sh специально откажет. Действия по замене повреждённого экземпляра требуют точного выбора целевых томов и сохранения исходного состояния.
