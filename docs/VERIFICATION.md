## Проверка обновлённого переносимого комплекта 26.09.2026

В отдельной Linux-копии переносимого проекта выполнено `python3 -m unittest discover -s tests -p 'test_*.py'`: **34 теста прошли**, включая Bash-сценарии `disable-payments.sh`, восстановление ключей и порядок DB-переключателя при смене режима. Локальный протокол задачи сохранён как `revision3/outputs/deploy-tests.log`. Отдельно `node --test tests/backup-notify.test.mjs`: **4 теста прошли** с моками БД и SMTP (support-профиль, явное выключение, отсутствие подписчиков, отсутствие старой записи TechnicalSettings). Сеть, настоящие письма и платежи в этих тестах не использовались.

Это не проверка установки ОС, systemd и публичного HTTPS на новом Ubuntu VPS и не полный прогон web/Mini App на итоговом коммите. Исторические результаты таблицы ниже остаются датированными.

Установка Docker на хост, systemd и запуск публичного Caddy были исключены из этого прогона. Они требуют отдельного контрольного развёртывания на новом Ubuntu VPS с настоящим DNS. Реальные деньги, SMTP и Telegram не использовались.

Нельзя интерпретировать результаты как полную проверку продаж или всей матрицы доступа. Открытые замечания перечислены в AUDIT.md.

Команды для повторения модульной проверки:

```bash
python3 -m unittest discover -s tests -v
bash -n install.sh deploy/dc
cd app
npm ci --no-audit --no-fund
npm run check
cd ..
node --test telegram-bot/*.test.mjs
node --test telegram-admin/tests/auth.test.mjs
```

GitHub Actions выполняет эти проверки и три Docker-сборки при push/pull request. Статус workflow смотрите для конкретного коммита: старый зелёный запуск не подтверждает новый код.
