# Telegram для заказов GSPro Store

Актуально по исходникам на 26.09.2026. Бот доставляет события и карточки заказов в закрытую группу; рабочие действия выполняются в Telegram Mini App с проверкой доступа и 2FA.

## Подключение

Нужен отдельный бот от BotFather и закрытая супергруппа с темами. Бот - администратор с правами управления темами, закрепления сообщений и приглашений. Если уже настроен webhook, worker останавливается: существующая интеграция не удаляется автоматически.

Токен, ключ внутреннего API и идентификаторы задаются в закрытой конфигурации. Пример переменных: `.env.telegram.example`; фактический Compose использует подготовленный `.env.runtime`. Операционный `.env.telegram`, если используется на сервере, также содержит секреты и не публикуется. Подготовка окружения описана в [production](../docs/production/README.md).

## Сотрудники и доступ

Актуальные права хранятся в `User`, `StaffAccess` и `StaffRolePolicy`. Изменение `operators.txt` само по себе доступ не выдаёт. Приглашение в группу также не выдаёт права на операции.

Кнопки ответа, статуса и списка заказов открывают Mini App. Она проверяет Telegram initData, связь с сотрудником, текущие права роли, канал доступа и 2FA. Внутренний bridge отклоняет прямые команды ответа и смены статуса; действия выполняются через проверенный доступ Mini App.

Чтобы прекратить чтение переписки бывшим сотрудником, удалите его и из самой группы Telegram. Отзыв прав сайта блокирует действия, но не удаляет участника группы.

## Работа

Одна тема соответствует одному покупателю; его заказы представлены отдельными карточками. Завершение одного заказа не закрывает общую тему. Для заказа без пользователя используется отдельный ключ, чтобы не объединять разных гостей.

Имя темы может содержать email покупателя: `topicName(customerEmail)` использует его при наличии, иначе короткий идентификатор. Поэтому нельзя считать Telegram каналом без персональных данных. Шаблон карточки содержит номер заказа, игру, товар, количество, сумму и статус; UID и пароли аккаунта в этот шаблон не включены.

- `/orders` обновляет закреплённый список: заказы в работе выше завершённых; порядок самих тем задаёт Telegram.
- «Ответить покупателю» и «Изменить статус» открывают соответствующий заказ в Mini App. Для действия нужны текущие права и 2FA.
- Обычные сообщения сотрудников в группе автоматически покупателю не отправляются.
- Смена статуса сама по себе не выполняет оплату или возврат денег через платёжного провайдера.

## Доставка и восстановление

События записываются в `TelegramEvent` в PostgreSQL вместе с изменением заказа или сообщением. Worker получает их через внутренний API, подтверждает доставку и повторяет неудачные попытки. При разрыве сети после принятия сообщения Telegram, но до подтверждения, текст может повториться: API Telegram не поддерживает ключ идемпотентности отправки.

Постоянный том `/data` хранит SQLite: связи тем и карточек, рабочее состояние и подтверждения. Это не одноразовый кэш. Не удаляйте том при обновлении. Запускайте одну реплику worker: экземпляры с одним токеном конфликтуют при polling.

При неопределённом результате создания темы бот не создаёт вторую автоматически. Проверьте существующие темы и журнал, затем выполните `/bind ORDER_ID TOPIC_ID` от разрешённого оператора. Если тема действительно не создана, создайте её вручную и привяжите после проверки идентификаторов.

Резервная копия должна включать PostgreSQL, `telegram_state` и закрытую конфигурацию с ключами. Для согласованного копирования SQLite остановите worker; сайт продолжит сохранять события. Полный архив восстановления не публикуется в GitHub.

Контейнер работает непривилегированным пользователем. Healthcheck контролирует последний успешный цикл; метка `unhealthy` сама по себе не запускает Docker restart. Проверяйте состояние, логи и фактическую доставку.

Локальные проверки из корня репозитория: `node --test telegram-bot/*.test.mjs`.

Связи сервисов и потоки данных: [архитектура и Obsidian Canvas](../docs/architecture/README.md).
