# GSPro: публичные инструкции

## Начать с самого простого способа

Для восстановления сохранённого GSPro на чистом **Ubuntu 24.04 x86_64** используйте интерактивный мастер. Все команды выполняются на новом VPS в SSH-терминале.

1. Откройте [новую инструкцию: короткий путь первым](server-setup/Инструкция_настройки_GSPro.md).
2. Скачайте [GSPro-Server-Setup.zip](GSPro-Server-Setup.zip) прямо на сервер командами из инструкции.
3. Запустите загрузчик recovery-kit из своего S3, расшифруйте полный снимок и пройдите опрос `configure-gspro.py`.
4. Проверьте подготовленные параметры, выполните staged restore и примените их по инструкции. Перед открытием сайта проверьте DNS, HTTPS, образы и S3.

[PDF инструкции нового VPS](server-setup/Инструкция_настройки_GSPro.pdf) · [Контрольная сумма ZIP](GSPro-Server-Setup.zip.sha256) · [Все документы](DOCUMENTS.md)

## Справочная копия README исходного проекта

# GSPro - Prod-1.1

Действующий production: `https://gspro.store`, корень на VPS — `/opt/gspro`. [Эксплуатация текущего сервера](docs/production/README.md). Установка через `install.sh` ниже относится к новому серверу; на текущем VPS используйте `deploy/dc` и `deploy/deploy-release.sh`.

Сайт, административная Telegram Mini App и Telegram-бот. Next.js, PostgreSQL 17, Docker Compose, Caddy. Переносимый комплект относится к **новому** Ubuntu VPS; рабочий сервер использует собственные файлы Compose и процедуры выпуска. База покупателей, исходные ключи и секреты в репозиторий не входят.

Текущий код включает подтверждение email при регистрации, уведомления в аккаунте, отмену заказа покупателем, 72-часовой срок до окончательного удаления аккаунта, четыре независимых SMTP-профиля и права сотрудников по разделам. Сотрудники работают в админке только с включённой 2FA и действующим доступом; владелец настраивает роли. Владелец управляет рассылкой отчётов о резервировании в своём профиле.

## Приложение на телефоне (PWA)

**[Открыть GSPro для установки на Android](https://gspro.store/)**. Откройте ссылку в Chrome, нажмите меню ⋮ и выберите «Установить приложение» либо «Добавить на главный экран» → «Установить». Названия пунктов зависят от браузера и его версии. Если приложение уже установлено, браузер может предложить открыть его.

**На iPhone:** откройте [GSPro](https://gspro.store/) в Safari → «Поделиться» → «На экран “Домой”». Если показан переключатель «Открывать как веб-приложение», включите его, затем нажмите «Добавить». [Инструкция Apple](https://support.apple.com/ru-ru/guide/iphone/iphea86e5236/ios). Установка GSPro на реальном iPhone в рамках этой проверки ещё не тестировалась.

Это устанавливаемая веб-версия магазина: иконка на телефоне, отдельное окно, тот же интерфейс, сервер, товары и заказы. Для работы нужен интернет. Отдельного APK и публикации Google Play/App Store нет. Ссылка открывает сайт; установка подтверждается пользователем в браузере и не запускается автоматически.

Настройки находятся в `app/app/manifest.js`: название, иконка, начальная страница `/` и режим `standalone`. При переносе на другой домен ссылкой установки будет адрес нового сайта. Офлайн-работа и push-уведомления в этом пакете не реализованы. Это приложение магазина, а административная Telegram Mini App открывается отдельно внутри Telegram.

## Установка на новый VPS

Нужен отдельный **Ubuntu 24.04 LTS, amd64**, root/sudo, минимум 2 vCPU / 4 ГБ RAM / 20 ГБ диска. Для сборки желательно 8 ГБ RAM, свободно минимум 10 ГБ. В DNS направьте домен на VPS; откройте TCP 80/443 и свой SSH-порт. Удалите неверную AAAA-запись, если IPv6 не настроен.

```bash
sudo apt-get update && sudo apt-get install -y git
sudo git clone https://github.com/nightengineer/GSPro.git /opt/gspro
cd /opt/gspro
sudo bash install.sh
```

Для приватного репозитория используйте read-only deploy key или авторизацию GitHub; токен не вставляйте в URL. Установщик спросит домен, email владельца и пароль. Подготовит Docker, ключи, базу, миграции, владельца, web, Mini App, HTTPS и служебные таймеры. Сборка бота также включена; подключение Telegram выполняется после получения токена.

```bash
sudo bash install.sh check
sudo bash install.sh telegram
```

После установки: `/auth/login` — вход, `/admin` — управление после включения обязательной 2FA. Настройте четыре SMTP-подключения: восстановление, маркетинг, заказы и поддержку; затем каталог, реквизиты и Telegram. Начальный каталог содержит выключенные демонстрационные позиции. **Новые реальные платежи выключены и в окружении, и в БД.** Не открывайте рекламный трафик до приёмки.

## Перенос существующего сайта

Инструкция по ручной доработке RU ↔ EN: [расположение словарей, пример правки и применение изменений](docs/TRANSLATIONS_RU_EN.md).

На новом VPS подготовьте закрытую папку `/root/gspro-transfer`: `database.dump` (`pg_dump -Fc`) и **исходный** `.env`; при наличии — `.env.telegram` и согласованный снимок бота `state.sqlite`, созданный через SQLite backup API при остановленном старом worker. Это отдельная защищённая передача, не GitHub. Без исходных ключей зашифрованные данные, игровые реквизиты и настройки почты не восстановить. Частный архив передачи хранится отдельно от публичного репозитория.

Если используете частный `GSPro-live-*.tar.gz`, перечисленные файлы находятся **внутри** архива в каталоге `transfer/`. После распаковки в `/root/gspro-transfer` используйте `--restore-dir /root/gspro-transfer/transfer` вместо пути в примере ниже; проверьте контрольные суммы до распаковки.

```bash
cd /opt/gspro
sudo bash install.sh install --restore-dir /root/gspro-transfer
```

База восстанавливается только в пустой проект. Пароли PostgreSQL создаются заново, ключи шифрования сохраняются. Учётные записи, роли, почтовые профили и каталог берутся из дампа, недостающие миграции применяются; новый владелец не создаётся. Переключатель новых платежей в БД принудительно выключается до публичного запуска. Бот не включается автоматически: сначала остановите его на старом VPS, затем выполните переключение по инструкции.

## Продажи и обслуживание

После сбоя существующего VPS: `sudo bash /opt/gspro/deploy/start-and-check.sh`.
Скрипт запускает существующие контейнеры и проверяет healthcheck и HTTPS.
[Инструкция запуска и проверки](docs/START_AND_CHECK_RU.md), включая режим `--check-only`.

После редактирования `.env`: `sudo bash /opt/gspro/deploy/check-env.sh`.
[Поэтапная диагностика окружения](docs/CHECK_ENV_RU.md) покажет конкретные поля с ошибками и неприменённые переменные без вывода секретов.

Быстро отключить новые реальные платежи и вернуться в no-production: `sudo bash /opt/gspro/deploy/disable-payments.sh`. [Порядок и ограничения переключения](docs/CHECK_ENV_RU.md#быстро-отключить-платежи-и-вернуться-в-прежний-предпродакшн).

```bash
sudo nano /opt/gspro/.env
sudo bash install.sh enable-sales
sudo bash install.sh check
```

`enable-sales` проверяет реквизиты, Platega и обязательные подтверждения, запускает режим production и только после этого включает переключатель приёма оплаты в БД. `disable-sales` сперва выключает переключатель БД. Отдельная настройка приёма оплаты доступна владельцу в админке; один лишь `PLATEGA_ENABLED=false` больше не гарантирует остановку новых платежей при сохранённом `checkoutEnabled=true`. Значения `true` не заменяют договоры, кассу и реальную проверку оплаты. Смена статуса заказа на REFUNDED сама по себе деньги не возвращает.

Другие команды: `start` применяет окружение и запускает сервисы; `disable-sales` отключает реальные платежи; `rebuild` пересобирает код, применяет миграции и перезапускает сервисы. Установщик не удаляет данные, не меняет SSH и не настраивает резервное копирование.
